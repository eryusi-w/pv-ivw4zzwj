AI가 멍청해지지 않게 하는 GSD Core의 페이즈 루프

#GSDCore#컨텍스트엔지니어링#스펙기반개발#클로드코드#커서#윈드서프#오픈코드#AI코딩#페이즈루프#개발프레임워크

문제 제기

AI 코딩 에이전트를 대규모 프로젝트에 활용하다 보면 공통적으로 겪는 문제가 있습니다. 바로 '컨텍스트 부패(Context Rot)'입니다. 대화가 길어질수록 AI의 기억력과 판단력이 흐려지고, 방대한 코드 베이스를 한꺼번에 읽으려다 보니 토큰 비용은 치솟는 반면 결과물의 품질은 오히려 떨어지는 현상입니다.

대부분의 AI 툴은 단순히 채팅 인터페이스를 제공할 뿐, 복잡한 개발 단계를 체계적으로 관리하지 못합니다. 무엇을 수정했는지, 현재 어떤 작업이 진행 중인지, 그리고 수정된 코드가 실제로 작동하는지 검증하는 과정이 누락되기 십상입니다. 이로 인해 개발자는 AI가 만든 버그를 직접 수정하느라 더 많은 시간을 허비하게 됩니다.

무엇인가

GSD Core(Git. Ship. Done.)는 AI 코딩 에이전트의 효율을 극대화하기 위한 '컨텍스트 엔지니어링 및 스펙 기반 개발 프레임워크'입니다. Claude Code, Cursor, Windsurf, OpenCode 등 거의 모든 주요 AI 코딩 환경을 지원하며, 난잡한 채팅 방식 대신 규율 있는 '페이즈 루프(Phase Loop)'를 도입하여 AI를 숙련된 엔지니어처럼 작동하게 만듭니다.

이 시스템의 핵심은 무거운 연구, 설계, 실행 작업을 각각 '신선한 컨텍스트(Fresh Context)'를 가진 서브에이전트에게 맡기는 것입니다. 이를 통해 메인 세션의 토큰 낭비를 최소화하고, 각 단계마다 구조화된 아티팩트(STATE.md, CONTEXT.md 등)를 생성하여 세션이 바뀌어도 작업의 연속성을 유지합니다. 한 마디로, AI의 성능을 안정적으로 유지하면서 큰 규모의 기능을 개발할 수 있게 돕는 OS와 같은 역할을 합니다.

동작 원리

GSD Core는 모든 이정표(Milestone)를 5단계의 엄격한 루프로 처리합니다. 먼저 **Discuss(논의)** 단계에서 구현 결정을 캡처합니다. 그다음 **Plan(계획)** 단계에서는 작업을 세분화하고 각 계획이 AI의 컨텍스트 창에 들어맞는지 검증합니다. 이어서 **Execute(실행)** 단계에서는 각 실행자가 200k 토큰의 깨끗한 환경에서 독립적으로 작업을 수행합니다.

끝으로 **Verify(검증)** 단계에서 빌드된 내용을 꼼꼼히 살피고 진단하며, 문제가 있다면 수정 계획을 세웁니다. 끝으로 **Ship(배포)** 단계에서 PR을 생성하고 현재 단계를 아카이브합니다. 이러한 구조적 반복을 통해 AI는 컨텍스트가 가득 차서 '멍청해지는' 지점을 피하고, 항상 최상의 상태에서 코드를 작성할 수 있게 됩니다.

설치와 첫 실행

GSD Core는 npm을 통해 간편하게 설치할 수 있습니다. 터미널에서 다음 명령을 실행하세요.

npx @opengsd/gsd-core@latest

명령을 실행하면 설치 마법사가 나타나 현재 사용 중인 런타임(Claude Code, Cursor 등)과 전역/지역 설치 여부를 묻습니다. 설치가 완료된 후, 새로운 프로젝트를 시작하거나 기존 코드베이스를 온보딩하려면 다음 명령을 사용합니다.

/gsd-new-project   # 새 프로젝트 시작
/gsd-onboard       # 기존 코드베이스 온보딩

온보딩이 완료되면 프로젝트 루트에 `.gsd` 관련 설정과 가이드 문서들이 생성되며, 이제 프레임워크가 정한 규칙에 따라 AI와 협업할 준비가 끝납니다.

핵심 사용법

가장 강력한 기능은 `STATE.md`와 `CONTEXT.md`를 통한 상태 관리입니다. AI에게 막연하게 "로그인 기능을 만들어줘"라고 시키는 대신, GSD Core 명령어를 사용하면 AI는 현재 어떤 단계에 있는지 스스로 인지합니다. 논의 단계에서 결정된 사항은 즉시 기록되어 다음 단계인 계획 수립의 근거가 됩니다.

특히 실행 단계에서 병렬 처리가 가능합니다. 복잡한 모듈을 여러 개 만들어야 할 때, GSD Core는 각 작업을 독립된 서브에이전트에게 할당하여 동시에 진행합니다. 각 에이전트는 불필요한 대화 기록 없이 오직 해당 작업에 필요한 정보만 가지고 코드를 짜기 때문에 정확도가 매우 높습니다. 작업이 끝나면 검증 단계에서 AI가 스스로 테스트를 돌려보고 통과 여부를 보고하게 만듭니다.

결과 읽는 법

GSD Core를 적용하면 프로젝트 폴더 구조가 매우 깔끔해집니다. `docs/phases/` 디렉토리 아래에 각 작업 단계별로 어떤 논의가 있었고, 어떤 계획이 세워졌으며, 결과가 어떠했는지가 마크다운 파일로 남습니다. AI와의 대화가 휘발되는 것이 아니라, 영구적인 기술 문서로 자산화되는 것입니다.

터미널 출력에서는 현재 진행 중인 페이즈(Phase)와 마일스톤의 상태를 시각적으로 확인할 수 있습니다. 예를 들어 실행 단계가 끝나면 "Execute phase complete. Move to Verify."와 같은 안내가 나오며, 체크리스트 형태로 남은 작업과 완료된 작업을 명확히 구분해 줍니다. 이는 개발자가 AI의 진행 상황을 한눈에 파악하고 통제권을 유지할 수 있게 해줍니다.

한계와 주의

GSD Core는 자유분방한 채팅보다는 정해진 프로세스를 따르는 프레임워크이므로, 처음 사용 시 다소 엄격하게 느껴질 수 있습니다. 간단한 오타 수정이나 단일 파일 변경 같은 사소한 작업에는 루프 전체를 도는 것이 과하게 느껴질 수 있습니다. 서브에이전트를 빈번하게 호출하는 방식이므로 API 호출 횟수 자체가 늘어날 수 있다는 점을 인지해야 합니다.

가장 주의할 점은 설치 시 안내에 따라 해당 런타임에 맞는 설정을 정확히 수행해야 한다는 것입니다. 수동으로 `agents/`나 `commands/`의 파일을 복사하면 런타임 간 호환성 문제가 발생할 수 있으니 반드시 공식 인스톨러를 사용하세요. 대규모 리팩토링 시에는 각 서브에이전트가 수정하는 파일이 겹치지 않도록 계획 단계에서 확실히 분리해주는 설계 능력이 필요합니다.

검증 루틴

프로젝트가 안정적으로 관리되고 있는지 확인하려면 다음 4가지를 체크하세요. 먼저 모든 기능 구현 전 `STATE.md`가 최신 상태로 업데이트되었는가? 그다음 실행 단계에서 서브에이전트가 짠 코드가 메인 브랜치의 컨벤션과 일치하는가? 이어서 검증(Verify) 단계에서 테스트 케이스가 하나 이상 실행되어 'Pass'를 기록했는가? 끝으로 배송(Ship) 단계 후에 관련 페이즈 문서가 정상적으로 아카이브되었는가? 이 루틴만 지키면 프로젝트 규모가 커져도 코드 품질이 일정하게 유지됩니다.

누구에게 필요한가

AI 에이전트로 단순한 토이 프로젝트를 넘어 실제 서비스용 대규모 코드베이스를 관리하고 싶은 시니어 개발자에게 가장 추천합니다. AI에게 코딩을 맡겼을 때 결과가 들쭉날쭉해서 실망했던 분들, 컨텍스트 용량 제한 때문에 매번 대화를 새로 시작하며 고생했던 분들에게 GSD Core는 최고의 해결책이 될 것입니다. 팀 단위로 AI와 협업할 때 표준화된 작업 절차가 필요한 경우에도 매우 유용합니다.

정리

GSD Core는 "Claude Code는 강력하지만, GSD Core는 그것을 신뢰할 수 있게 만든다"는 말로 요약됩니다. 컨텍스트의 부패를 막고 체계적인 5단계 루프를 통해 AI를 고성능 개발 도구로 변모시킵니다. 이제 막막한 거대 프로젝트 앞에서 AI의 혼란을 지켜보지 마세요. GSD Core의 엄격한 규율 위에서 당신의 코드는 더 빠르고 정확하게 완성될 것입니다.
