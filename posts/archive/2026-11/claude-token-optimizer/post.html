토큰이 새는 지점

Claude Code를 쓰다 보면 같은 작업을 하는데도 세션마다 비용이 크게 달라집니다. 원인은 대개 세 가지입니다. 모호한 요청에 대한 추측, 긴 코드 블록의 반복 출력, 그리고 끝나고 나서 하는 상세한 설명입니다.

claude-token-optimizer는 이 세 가지를 규칙으로 막는 스킬 모음입니다. 모델을 바꾸는 도구가 아니라, 에이전트의 출력 습관을 파일로 고정하는 도구입니다.

저장소 구성과 라이선스

저장소에는 antigravity, antigravity2.0, ultimate-protocol 세 폴더가 있고, 각 폴더에 SKILL.md가 들어 있습니다. 라이선스는 MIT이고, 커밋 수와 별 수가 많지 않은 개인 프로젝트입니다.

이 점은 미리 알아 두는 편이 좋습니다. 문서에 적힌 절감률은 작성자가 자기 환경에서 잰 값이고, 독립 검증을 거친 수치는 아닙니다.

세 가지 프로토콜 비교

폴더마다 목적이 다릅니다. 일상 코딩에는 안티그래비티가, 자동화 파이프라인에는 얼티밋이 맞습니다. 표로 정리하면 선택이 단순해집니다.

프로토콜특징맞는 상황
Antigravity V1짧은 답변, 즉시 수정일상 코딩
Antigravity 2.0계획을 .md 파일로 분리큰 작업, 팀
UltimateJSON만 출력자동화 파이프라인

V1과 2.0의 차이는 출력 위치입니다. 계획과 긴 코드 블록을 채팅창에 쏟아내는 대신 파일로 쓰면, 세션 컨텍스트에 남는 양이 줄어듭니다.

설치: 스킬 폴더에 넣기

설치는 저장소를 받아 스킬 폴더에 복사하는 방식입니다. 특정 모델이나 API 키를 요구하지 않아 Claude Code만 있으면 됩니다.

# 저장소 받기
git clone https://github.com/KINGSTAR-OMEGA/claude-token-optimizer.git

# 스킬 폴더 생성 후 프로토콜 복사 (README 기준)
mkdir -p ~/.claude/skills
cp -r claude-token-optimizer/antigravity ~/.claude/skills/

# Windows PowerShell
New-Item -ItemType Directory -Force "$HOME\.claude\skills"
Copy-Item -Recurse .\claude-token-optimizer\antigravity "$HOME\.claude\skills\"

복사 후 Claude Code를 다시 열고 "Activate Antigravity Protocol"처럼 이름을 불러 활성화합니다. 스킬이 목록에 보이지 않으면 SKILL.md가 폴더 루트에 있는지 확인합니다.

활성화 후 달라지는 것

가장 먼저 체감되는 변화는 되묻는 동작입니다. 요청이 모호하면 추측해서 진행하지 않고 선택지를 제시합니다. 처음에는 느리게 느껴지지만, 잘못된 방향으로 만 줄을 생성하는 일이 줄어듭니다.

두 번째는 완료 보고입니다. 단계별 설명 대신 변경 결과만 남기므로, 대화 기록을 다시 읽는 비용도 줄어듭니다.

# 활성화 예시
"Activate Antigravity Protocol"

# 이후 지시는 그대로
"src/api/client.ts 의 재시도 로직에서
 지수 백오프가 두 번 적용되는지 확인하고,
 중복이면 한 곳만 남겨줘."

지시 내용을 바꿀 필요는 없습니다. 출력 규칙만 바뀌기 때문에, 기존에 쓰던 프롬프트를 그대로 재사용할 수 있습니다.

절감 효과를 재는 방법

절감률은 반드시 자기 작업으로 재야 합니다. 같은 작업을 프로토콜 없이 한 번, 켜고 한 번 실행하고 사용량 화면의 토큰 수를 비교하는 방식이 가장 단순합니다.

측정할 때는 작업 난이도를 고정해야 합니다. 파일 수, 테스트 개수, 요구사항을 동일하게 두고 비교하지 않으면 차이가 프로토콜 때문인지 작업량 때문인지 구분되지 않습니다.

기록은 세 줄이면 충분합니다. 실행에 쓴 시간, 사용량 화면의 토큰 수, 결과를 검토하는 데 걸린 시간입니다. 세 번째 항목이 특히 중요합니다. 토큰은 줄었는데 검토 시간이 늘었다면 총비용은 그대로이기 때문입니다.

측정 결과는 팀 규칙으로 남겨 두는 편이 좋습니다. 같은 저장소에서 같은 유형의 작업을 반복한다면, 어떤 프로토콜이 어떤 난이도에서 유리한지 표 한 장으로 정리됩니다.

언제 효과가 없는가

탐색이 많은 작업에서는 효과가 줄어듭니다. 원인을 찾기 위해 여러 파일을 읽어야 하는 상황은 출력이 아니라 입력이 비용을 만듭니다. 이때는 출력 규칙을 조여도 절감 폭이 작습니다.

문서화가 중요한 팀에서는 불리합니다. 왜 그렇게 고쳤는지 설명이 남지 않으면 나중에 리뷰 비용이 늘어납니다. 커밋 메시지나 PR 설명으로 보완하는 편이 낫습니다.

Ultimate 모드는 어디에 쓰나

Ultimate는 대화 텍스트를 금지하고 JSON만 돌려주는 모드입니다. 사람이 읽을 필요가 없는 자동화 단계, 예를 들어 스크립트가 결과를 파싱해 다음 단계로 넘기는 구조에 맞습니다.

대화형 작업에 쓰면 오히려 불편합니다. 결과를 사람이 해석해야 할 때는 V1이나 2.0이 적합합니다.

주의할 점

이 프로젝트는 최근에 만들어진 소규모 저장소입니다. 문서의 벤치마크 표는 작성자의 5개 과제 결과이고, 저장소가 바뀌면 동작도 달라질 수 있습니다. 도입 전에 SKILL.md 내용을 직접 읽어 보는 편이 안전합니다.

스킬은 에이전트의 행동 규칙을 바꾸는 파일이므로, 신뢰할 수 없는 저장소의 스킬을 그대로 넣는 것은 권장되지 않습니다. 어떤 지시가 들어 있는지 확인한 뒤 복사하세요.

정리: 출력 습관을 규칙으로

토큰 비용은 모델 선택보다 출력 습관에서 갈리는 경우가 많습니다. 계획은 파일로, 완료 보고는 한 줄로, 모호하면 되묻기 — 세 가지 규칙만으로도 체감 차이가 납니다.

이 저장소를 쓰지 않더라도 같은 규칙을 CLAUDE.md에 직접 적어 두는 방법이 있습니다. 도구를 들이기 전에 규칙부터 정리해 보는 편이 오래 갑니다.

정리하면 이렇습니다. 출력 규칙은 비용에 직접 영향을 주고, 그 규칙은 파일로 남길 수 있습니다. 남의 저장소를 그대로 쓰기보다, 우리 팀에 필요한 규칙 세 개를 골라 직접 적는 것이 가장 현실적인 출발점입니다.
