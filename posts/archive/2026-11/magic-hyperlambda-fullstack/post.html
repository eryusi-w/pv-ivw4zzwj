문제 제기: '앱을 말로 만든다'의 실제 범위

Lovable, Bolt, Replit 같은 서비스는 "말로 풀스택 앱을 만든다"고 광고합니다. 그런데 결과물은 대부분 프런트엔드 중심이고, 백엔드·데이터베이스·인증·배포는 서드파티 BaaS에 맡기게 됩니다. 데이터를 완전히 내 것으로 두려면 결국 다시 조립해야 합니다.

그런데 polterguy/magic은 반대 방향을 갑니다. 말로 만든 결과물이 내 하드웨어 위에서 돌아가는 전체 스택이고, 백엔드 코드까지 통째로 소유합니다. MIT 라이선스, .NET 10 기반입니다.

데이터베이스, 보안 API, 비즈니스 로직, 프런트엔드까지 — 저장하면 바로 실행되는 풀스택이 내 서버에서 돌아갑니다.

무엇인가: magic과 Hyperlambda

magic은 자연어를 풀스택 앱으로 바꾸는 플랫폼입니다. CRM, 관리자 패널, 예약 시스템, 내부 도구, 데이터베이스 위의 AI 에이전트, 챗봇, 서드파티 API 래퍼, MCP 도구 서버, 백그라운드 잡까지 만들 수 있습니다.

핵심은 실행 모델인 Hyperlambda(하이퍼람다)입니다. 일반적인 "자연어 → JSON 워크플로" 방식이 아니라, 컴파일된 .NET 런타임에서 실행되는 언어입니다. README가 주장하는 성능 수치도 이 차이에서 나옵니다 — Chinook 읽기 엔드포인트 기준 Hyperlambda가 FastAPI 4워커의 약 3.7배 처리량(초당 64,664 요청 vs 17,686)을 냈다고 측정했습니다. 같은 머신에서 코어를 더 쓴 측정이라 효율 비교는 아니라고 스스로 밝힙니다.

GitHub 별 1,200개 수준의 초기 프로젝트입니다.

60초 안에 띄우기

Docker Compose 한 줄이면 됩니다.

curl -fsSL https://hyperlambda.dev/docker-compose.yaml | docker compose -f - up

그 다음 localhost:5555(대시보드)를 열고 백엔드 localhost:4444를 가리키게 한 뒤, root/root로 로그인합니다. 기본 자격 증명은 개발용이니 실제 운영 전에 반드시 바꾸세요.

대시보드 사이드바가 플랫폼 전체입니다. Hyper IDE(파일 편집·실행·리플레이), Playground(저장 전 실행), SQL Studio, Endpoint Generator(테이블을 보안된 CRUD 엔드포인트로), 사용자·역할, 예약 작업, 머신러닝, 플러그인 스토어가 있습니다.

저장하면 바로 실행 — 배포 단계가 없다

magic의 가장 큰 차별점은 "저장하고 바로 테스트"입니다. 코드를 저장하면 배포나 퍼블리시 단계 없이 바로 실행할 수 있습니다. Hyper IDE에는 프롬프트 바가 있어서 "이 파일에 이런 기능을 만들어 줘"라고 말하면 생성기가 코드를 직접 채웁니다.

API Wizard는 데이터베이스를 가리키면 보안된 REST 엔드포인트 54개를 자동 생성합니다. 기존 MySQL·PostgreSQL·SQL Server·MariaDB 스키마를 가리켜도 CRUD API가 몇 초 만에 나옵니다. OpenAPI·Swagger URL을 붙여 넣으면 Stripe·GitHub·Slack 같은 서드파티 API를 감싼 타입 지정된 엔드포인트도 만들어 줍니다.

MCP로 엔드포인트를 도구로

mcp 플러그인을 설치하고 Claude Code·Cursor·Codex 같은 MCP 클라이언트를 클라우드릿에 연결하면, modules 폴더의 모든 HTTP 엔드포인트가 에이전트가 호출할 수 있는 도구가 됩니다.

README는 이 방식이 토큰 소비를 약 80% 줄인다고 주장합니다(자체 측정값). 에이전트가 매번 코드를 생성하는 대신 이미 존재하는 엔드포인트를 도구로 호출하기 때문입니다. 계산기는 hyperlambda.dev에 공개돼 있습니다.

환각하지 않는 함수: AST 생성

magic은 자체 독점 LLM으로 Hyperlambda를 생성합니다. 특이한 점은 텍스트가 아니라 AST(추상 구문 트리)를 생성한다는 겁니다. 출력이 분석돼서 존재하지 않는 함수 호출이 있으면 거부됩니다. 즉 LLM이 논리적으로 틀린 코드를 쓸 수는 있어도, 존재하지 않는 함수를 호출하는 코드는 원천적으로 나올 수 없습니다.

어휘(vocabulary)를 제한할 수도 있어서, 에이전트가 필요할 때 자기 도구 공간을 키우되 공격 표면을 넓히지 않는 구조를 만들 수 있다고 설명합니다.

보안 모델: 샌드박스와 RBAC

Hyperlambda는 샌드박스에서 실행되고 샌드박스 밖 파일 시스템 접근이 없습니다. RBAC로 개별 함수 호출을 화이트리스트할 수 있어서, 서버가 출처를 모르는 코드를 입력으로 받아도 안전하게 실행할 수 있다고 주장합니다. README는 "자연어 API가 3개월간 임의의 공개 입력을 받아 왔는데 성공한 익스플로잇이 없다"며 백엔드의 심각한 보안 버그를 찾으면 100달러를 주겠다고 공지합니다.

다만 이는 제작자의 주장입니다. 인터넷에 노출되는 서비스라면 포트 바인딩·인증·백업을 직접 점검해야 합니다.

기능 더 보기: Chat Ops·Rewind·헤드리스 브라우저

README에는 대시보드만으로도 놀라운 기능이 더 있습니다.

  • Chat Ops: 대시보드 어디서든 Ctrl+.를 누르면 클라우드릿과 대화하는 패널이 열립니다. "이 사이트를 크롤해서 CRUD API 만들어 줘"라고 하면 함수가 실제로 실행되고, 각 호출이 상태 표시(실행 중·성공·실패)와 함께 기록됩니다.
  • Rewind: 실행을 기록했다가 단계별로 되짚어 볼 수 있는 디버거입니다. 코드가 던진 지점의 상태가 그대로 남아 있어 "왜"를 볼 수 있습니다. 메모리에만 존재하고 디스크에 쓰지 않습니다.
  • 헤드리스 브라우저: PuppeteerSharp이 내장돼 있어 에이전트가 폼 작성·클릭 같은 브라우저 작업을 사람처럼 수행합니다.
  • Sandbox API: 호출자가 보낸 코드를 역할별 화이트리스트 안에서 실행하는 엔드포인트를 만들 수 있습니다. README는 읽기 전용 Chinook 샘플 DB에 guest 권한만 준 라이브 데모를 공개해 두었습니다.
  • Git·OIDC·DIY 홈클라우드: 프로젝트 커밋·푸시가 내장돼 있고, Google·GitHub·Entra ID 등 OIDC 로그인을 지원하며, Mac Mini + Cloudflare 터널로 집에서 서비스할 수도 있습니다.

Python·Bash 스크립트 생성·실행도 되지만, README는 root로 로그인했을 때만 가능하다고 경고합니다. 보안 모델이 구멍을 줄여도 만능은 아니니, 제3자가 코드를 실행하게 하는 엔드포인트는 노출하지 말라고 덧붙입니다.

한계와 주의

Hyperlambda는 생소한 언어입니다. 생태계가 .NET 중심이고, 팀에 .NET 경험이 없다면 학습 비용이 생깁니다. 또한 "LLM이 함수를 환각하지 않는다"는 보장이 논리적 정확성까지 보장하지는 않습니다 — 존재하는 함수로 엉뚱한 로직을 짤 수는 있습니다.

Docker Compose로 띄우는 구조라 운영 부담(업데이트, 백업, 모니터링)은 사용자 몫입니다. SonarCloud 배지로 품질 지표를 공개하고 있지만, 초기 프로젝트라는 점은 감안해야 합니다.

도입 전 체크리스트

확인할 것 4가지

✓ 인프라 — Docker가 있고 5555·4444 포트를 외부에 열지 않는 환경인지

✓ 자격 증명 — 기본 root/root를 즉시 변경하고 RBAC 역할을 설계할지

✓ 언어 — Hyperlambda를 팀이 유지보수할 수 있을지, 아니면 생성 코드만 관리할지

✓ 검토 — AI가 생성한 파일을 사람이 읽고 승인하는 절차

정리

magic은 "말로 풀스택 앱"을 내 하드웨어에서 끝까지 소유하는 방식으로 구현한 프로젝트입니다. Hyperlambda라는 컴파일된 런타임 위에서 돌아가고, 저장 즉시 실행되며, MCP로 엔드포인트를 에이전트 도구로 바꿉니다.

오늘 해 볼 일은 간단합니다. Docker Compose 한 줄로 띄우고 localhost:5555에서 API Wizard로 기존 DB를 가리켜 보세요. 엔드포인트 54개가 생기는 걸 보면 이 프로젝트의 스케일이 보입니다.
