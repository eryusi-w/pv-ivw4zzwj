"내 컴퓨터에서는 되는데 서버에서는 안 돼요." 개발자라면 한 번쯤 겪는 상황입니다. Docker는 이런 환경 차이를 없애주는 컨테이너 도구입니다. 설치부터 첫 실행까지, 초보가 꼭 알아야 할 것만 정리했습니다.

Docker가 뭔가요

Docker는 프로그램을 "컨테이너"라는 격리된 상자에 담아 실행하는 플랫폼입니다. 상자 안에는 프로그램 실행에 필요한 라이브러리와 설정이 통째로 들어 있어서, 어느 컴퓨터에서 실행해도 똑같이 동작합니다. 무거운 가상머신(VM)과 달리 OS 커널을 공유해서 가볍고 빠릅니다.

핵심 개념은 두 가지입니다. 이미지는 실행할 프로그램의 설계도(레시피)이고, 컨테이너는 그 이미지로 실제 실행 중인 상자입니다. 이미지는 여러 개 만들어 재사용하고, 컨테이너는 실행할 때마다 새로 뜹니다.

어떻게 설치하나요

운영체제별로 공식 설치 방법이 다릅니다.

환경설치 방법
Windows / MacDocker Desktop 설치 (docker.com에서 무료 다운로드)
Linux배포판 패키지 또는 공식 저장소로 Docker Engine 설치

설치 후 터미널에서 버전을 확인하면 준비 끝입니다.

docker --version
# 예: Docker version 27.x.x

참고로 Docker Desktop은 개인과 소규모 조직에서 무료입니다. 직원 250명 이상이거나 연매출 1천만 달러 이상인 회사는 유료 구독이 필요하다는 점만 알아두세요.

첫 실행해보기

Docker가 제대로 설치됐는지 확인하는 가장 빠른 방법은 예제 컨테이너를 실행하는 것입니다.

docker run hello-world

처음 실행하면 이미지를 자동으로 내려받고, "Hello from Docker!" 메시지를 출력하면 성공입니다. 실제로 쓰는 흐름은 이렇습니다.

docker pull nginx        이미지 내려받기
docker run -d -p 8080:80 nginx   백그라운드 실행 + 포트 연결
docker ps               실행 중인 컨테이너 목록
docker stop 컨테이너ID    컨테이너 중지

실제로 어디에 쓰이나요

실무에서는 대부분 개발 환경 통일과 서버 배포에 씁니다.

  • 개발 환경: "제 컴퓨터에선 되는데"를 없애려고 팀원 모두가 같은 컨테이너 환경을 씁니다
  • 서버 배포: 만든 컨테이너를 그대로 서버에 올려서 어디서든 같은 버전이 돌아갑니다
  • 여러 서비스 묶기: 웹서버+DB처럼 같이 돌아야 하는 프로그램을 docker compose로 한 번에 띄웁니다

초보가 주의할 점

Docker는 강력하지만 처음부터 다 알 필요는 없습니다. 아래 세 가지만 기억하세요.

  • 컨테이너는 이미지와 다릅니다 — 실행 중인 건 컨테이너, 설계도는 이미지
  • 컨테이너를 멈춰도 데이터는 안 남을 수 있습니다 — 중요한 데이터는 볼륨으로 따로 저장해야 합니다
  • 처음엔 Docker Desktop + docker compose로 시작하면 충분합니다

정리

Docker는 "어디서든 같은 환경으로 실행"을 가능하게 하는 도구입니다. docker run hello-world부터 시작해서, pull→run→ps→stop 순서만 익히면 됩니다. 다음 단계로는 docker compose로 여러 서비스를 묶어보면 좋습니다.

참고: Docker 공식 문서(docs.docker.com)와 Docker Desktop 다운로드 페이지 기준입니다.
