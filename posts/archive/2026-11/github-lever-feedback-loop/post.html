문제 제기: 에이전트가 스스로 검증하지 못하는 이유

코딩 에이전트는 정말 좋아졌습니다. 그런데 한 가지가 비어 있습니다. 스스로 확인할 방법입니다.

테스트 스위트가 느리다는 걸 스크롤 버벅임을 눈으로 본다는 걸, 에이전트는 스스로 알 수 없습니다. 결국 사람이 스크린샷을 붙여 주고, "이거 다시 돌려 봐"라고 하고, 자정에 CI를 다시 실행합니다. 에이전트가 아무리 똑똑해도, 숫자와 측정 방법과 "좋아졌다"의 기준을 모르면 몇 시간이고 갈아 넣어도 방향을 잃습니다.

피드백 루프를 설정하는 게 어려워서 사람들이 건너뜁니다. 그 질문들을 대신 물어보고 답을 적어 주는 도구가 lever입니다.

무엇인가: lever

github/lever는 코딩 에이전트용 피드백 루프를 제공하는 GitHub 공식 Copilot 플러그인입니다. MIT 라이선스, GitHub 별 275개로 아직 초기 단계("Early")라고 스스로 밝힙니다.

핵심 발상: 지표·측정법·합격 기준을 정해 두면 에이전트는 몇 시간이고 스스로 반복할 수 있습니다. 반대로 그것들이 없으면 사람이 루프 자체가 됩니다. lever는 그 루프를 세팅하는 번거로운 질문들(뭘 재지? 얼마나 노이즈가 있지? 진짜 개선이 뭐지? 언제 멈추지?)을 대신 물어보고, 답을 문서로 남긴 뒤 에이전트가 그걸 기준으로 반복하게 합니다.

GitHub에서 AI를 가장 먼저 쓴 엔지니어들의 실제 워크플로(CI 속도 개선, 크레이트 분할, 무인 딜리버리, 자동화)를 마이닝해 한 명령으로 만든 프로젝트입니다.

설치: 마켓플레이스 두 줄

Copilot CLI 기준으로는 마켓플레이스 추가와 플러그인 설치 두 줄입니다.

copilot plugin marketplace add github/lever
copilot plugin install lever@lever

Copilot 앱에서는 ghapp://plugins/install?source=lever%40lever&marketplace=github%2Flever 링크를 열어 확인만 누르면 됩니다. 저장소 단위로 넣으면 클라우드의 Copilot 코딩 에이전트도 스킬을 씁니다.

# 리포 단위 설치 — 에이전트도 읽게
mkdir -p .github/skills
cp -r path/to/lever/skills/* .github/skills/
cp -r path/to/lever/{docs,templates,config,automations} .github/

개발용으로는 저장소를 클론해 copilot plugin marketplace add ./lever로 로컬에서 바로 고쳐 쓸 수 있습니다.

Loop Card: 루프를 카드로 만든다

가장 인상적인 개념은 Loop Card입니다. /lever loop에 불만을 말하면 — 예: "테스트 스위트가 느린 것 같아, 일단 카드만" — lever가 지표, 측정 방법, 노이즈 정도, 무엇을 성공으로 칠지를 담은 카드를 만들어 줍니다. 이 단계에서는 아무것도 푸시하거나 머지하지 않습니다.

루프를 만들기 전에 루프를 먼저 합의하는 겁니다. 에이전트가 밤새 돌아도 "느려졌다"가 주관이 아니라 숫자로 판정되게 하는 장치죠.

/lever loop our test suite feels slow. just the card, don't change anything

동사 지도: BUILD·LOOP·RUN·YOU

lever는 단일 명령이 아니라 동사(verb) 모음입니다. 어떤 걸 하든 /lever <불만>으로 말하면 lever가 알맞은 동사를 골라 줍니다.

분류 동사 하는 일
만들기 brief, deliver, refactor 20단어짜리 요청을 무인 실행 가능한 브리프로, 큰 기계적 변경을 레인 병렬로
루프 loop, arms, review Loop Card 생성, 아이디어별 에이전트 대조 실험, 여러 모델 교차 리뷰
실행 automate, shepherd, land 잡일을 일시정지된 자동화로, PR 스택을 초록으로 유지, 머지 계획
나에게 맞추기 mirror, steer, autonomy, spend 지난 30일 세션에서 반복 패턴 분석, 교정 한 번이면 규칙화, 자율성·모델 예산 설정

다이얼: autonomy와 spend

lever의 두 개의 다이얼이 실제 권한을 결정합니다.

  • Autonomy L0~L5: 누가 머지하는가. L0은 제안만, L2는 PR을 초록으로 만들고 사람은 머지, L5는 머지·릴리스·감시까지. ~/.copilot/lever.yml에 저장되고, 리포의 브랜치 보호 규칙이 항상 우선합니다. README는 L2에서 시작해 신뢰가 쌓이면 올리라고 권합니다.
  • Spend: standard·high·max — 모델 티어, 병렬 레인 수, 리뷰 깊이, 실행 빈도. 리포가 .github/lever.yml로 상한을 둘 수 있습니다.

/lever setup을 처음 한 번 돌리면 이 두 다이얼을 물어보고 설정 파일을 만들어 줍니다. 팀 단위로는 config/autonomy.example.yml을 .github/lever.yml로 복사하면 됩니다.

mirror와 steer: 나에게 맞추기

재미있는 부분이 하나 더 있습니다. /lever mirror는 지난 30일의 내 프롬프트 세션 기록을 읽어 "내가 계속 반복하는 것"을 점수표로 보여 줍니다. /lever steer는 그런 반복 교정을 한 번 말하면 다시는 안 하게 규칙으로 만듭니다. 즉 lever 자체도 사용자에게 맞춰 진화하는 구조입니다.

README는 "이 스킬들은 우리 팀에 맞춰져 있다. fork해서 네 방식에 맞게 비틀어라"라고 명시합니다. MIT 라이선스라 자유롭게 개조할 수 있습니다.

한계와 주의

먼저 범위입니다. lever는 Copilot 생태계 전용입니다. Claude Code나 다른 에이전트에서는 동작하지 않습니다. 리포 단위 설치로 스킬을 뽑아 쓰는 방법이 있긴 하지만 플레이북이 Copilot 작업 흐름에 맞춰져 있습니다.

둘째, "Early" 단계라고 스스로 밝힙니다. 자동화가 일시정지 상태로 만들어지고 dry-run 후 켜는 구조라 안전장치는 있지만, 자율성 다이얼을 올릴수록 실수 비용도 커집니다. 셋째, 피드백 루프의 품질은 Loop Card의 지표가 얼마나 좋은지에 달렸습니다. 노이즈 큰 지표를 고르면 에이전트가 밤새 헛돌 수 있습니다.

도입 전 체크리스트

확인할 것 4가지

✓ 환경 — GitHub Copilot(앱/CLI)을 쓰는지, 다른 에이전트면 대안 검토

✓ 첫 동사 — /lever loop로 Loop Card만 만들어 루프 품질부터 확인

✓ 자율성 — L0~L2에서 시작하고, 브랜치 보호 규칙과 충돌 없는지

✓ 비용 — spend 다이얼과 리포별 상한(.github/lever.yml) 설정

정리

lever는 "에이전트가 스스로 검증하게 만드는 법"을 한 명령으로 만든 GitHub의 Copilot 플러그인입니다. Loop Card로 루프를 먼저 합의하고, autonomy·spend 다이얼로 권한을 조절하며, mirror·steer로 나에게 맞춥니다.

오늘 해 볼 일은 간단합니다. 설치 후 /lever loop에 지금 가장 느리거나 불안정한 작업을 말해 보세요. 코드가 바뀌지 않아도 Loop Card가 나오면, 다음엔 그 지표로 에이전트를 밤새 돌릴 수 있습니다.
