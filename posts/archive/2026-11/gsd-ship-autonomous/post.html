"GSD Shipping"으로 검색하는 분들은 GSD의 ship 단계를 찾는 중일 가능성이 큽니다. Get Shit Done의 자율 실행과 PR 생성까지, 기존 페이즈 루프 글과 다른 '실행·출시' 쪽을 정리했습니다.

GSD 2는 프롬프트가 아니라 에이전트

원래 GSD는 Claude Code에 프롬프트를 주입하는 방식이었습니다. 지금의 GSD 2는 Pi SDK 위에 만든 독립 CLI로, 컨텍스트 관리·세션·git·비용 추적을 코드로 직접 처리합니다.

npm install -g gsd-pi

프로젝트 폴더에서 gsd를 실행하면 대화형 TUI가 열리고, 웹 UI(gsd --web)도 있습니다.

/gsd와 /gsd auto — 두 가지 모드

작업 방식은 둘로 나뉩니다.

  • /gsd — 한 작업 단위씩 실행하고 마법사로 결과를 보여주는 스텝 모드
  • /gsd auto — 마일스톤이 끝날 때까지 자율 진행하는 자동 모드

auto 모드는 SQLite 데이터베이스가 상태의 기준입니다. 다음 작업을 DB에서 읽고, 새 에이전트 세션에 필요한 컨텍스트만 인라인해서 넣고, 끝나면 결과를 저장한 뒤 다음 단위로 넘어갑니다.

작업 단위 구조

GSD는 목표를 세 단계로 쪼갭니다.

  • 마일스톤 — 프로젝트를 의미 있게 앞으로 나아가게 하는 출시 단위
  • 슬라이스 — 마일스톤 안의 응집된 작업 묶음
  • 태스크 — 한 세션이 완료·커밋하는 원자 작업

각 단위는 plan → implement → verify → commit → reassess 순환을 돌고, 마일스톤 작업은 git worktree로 격리됩니다.

Shipping — 검증을 통과해야 PR이 열린다

"GSD Shipping"의 실체는 /gsd:ship(런타임에 따라 /gsd-ship, Codex는 $gsd-ship) 명령입니다. 완료된 phase 작업을 모아 PR을 만들고, 본문은 ROADMAP·SUMMARY 같은 기획 산출물에서 자동 생성합니다.

게이트가 있습니다. verification.status가 passed일 때만 진행되고, gaps_found·human_needed 등이면 차단됩니다. PR 본문에는 phase 목표, 변경 요약, 충족한 요구사항 ID, 검증 상태가 들어갑니다.

/gsd:ship 4          # 4번 phase를 PR로
/gsd:ship 4 --draft  # 드래프트 PR로

사전 조건으로 gh CLI 인증과 jq가 필요합니다.

주의할 점

auto 모드는 "돌아다니는 동안" 코드가 커밋되므로, 민감한 저장소나 진행 중인 작업이 있는 브랜치에서는 스텝 모드가 안전합니다. 또한 검증 게이트가 있어도 최종 리뷰는 사람이 해야 합니다.

정리

GSD Shipping은 /gsd:ship 명령으로, 검증 통과한 phase를 PR로 만드는 단계입니다. 자율 실행은 /gsd auto, 단계별 확인은 /gsd — 목적에 맞게 고르세요.
