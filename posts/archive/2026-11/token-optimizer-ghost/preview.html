컨텍스트가 나빠지는 이유

Claude Code를 반나절 켜 두면 같은 파일을 세 번 읽고, 테스트 로그를 통째로 다시 올린다. 모델이 갑자기 멍청해진 게 아니라 컨텍스트가 같은 내용으로 채워진 것이다. 압축이 한 번 일어나면 요약에서 빠진 규칙 하나 때문에 방금 고친 걸 다시 고치게 된다.

이 도구가 찾는 것

alexgreensh/token-optimizer가 찾는 건 README가 유령 토큰(ghost token)이라고 부르는 것들이다. 쓰이지 않으면서 자리만 차지하는 문장, 지난 턴에 이미 본 로그 같은 것이다. 이 도구는 그 낭비를 알려 주는 데서 멈추지 않고, 훅을 걸어서 실제로 줄인다.

표적은 명령 출력, 같은 파일 재읽기, 검색 결과, 4KB가 넘는 tool 결과 네 군데다. 명령 출력 하나만 봐도 111개 명령과 22개 패턴 계열을 다룬다.

압축 대상원래줄어든 뒤
pytest 실행 로그564 토큰115 토큰
검색·grep 결과500줄상위 20줄 + 개수
같은 파일 다시 읽기2,000 토큰약 50 토큰(diff만)
파일 구조 맵720KB250 토큰(시그니처만)

이 숫자는 저장소가 자체 벤치마크로 내놓은 값이다. 같은 조건에서 다시 재 본 값은 아니다. 별은 약 2,800개(2026-11-01 기준), 최신 릴리스는 v5.13.16이고 Claude Code 말고도 Codex, Cursor, Copilot, OpenCode를 지원한다.

설치

Claude Code라면 플러그인 두 줄이 전부다.

/plugin marketplace add alexgreensh/token-optimizer
/plugin install token-optimizer@alexgreensh-token-optimizer

설치한 뒤 /token-optimizer를 한 번 실행하면 훅이 등록되고, 그 다음부터는 알아서 돈다. 여기서 놓치기 쉬운 게 자동 업데이트다. Claude Code는 서드파티 마켓플레이스의 자동 업데이트를 기본으로 꺼 두기 때문에, /plugin의 Marketplaces 탭에서 alexgreensh-token-optimizer를 골라 직접 켜 줘야 한다. Windows에서는 install.sh를 쓰지 말고 플러그인 설치만 쓰라고 README가 못 박아 둔다.

스캔 결과 읽기

첫 감사는 CLAUDE.md, 스킬, MCP 서버, 메모리, 세션 로그를 나눠서 본다. 에이전트 여섯 개를 병렬로 붙이는 식이라, 결과도 "이걸 지우세요"가 아니라 "이 파일이 매 세션 몇 토큰을 쓰고 있다"에 가깝다. 숫자가 나오면 고칠지 말지 판단하기가 훨씬 쉽다.

/token-optimizer
quick
report
savings

quick은 10초짜리 상태 점검, report는 컴포넌트별 토큰 분해, savings는 그걸 돈으로 환산한 값이다. 감사 결과는 항목마다 적용할지 물어보므로 지침 파일이 통째로 갈아엎히는 일은 없다. 다만 반복이 필요한 안전 규칙까지 줄이라고 하면 그건 사람이 남겨야 한다.

압축과 복구

압축은 삭제가 아니다. 4KB가 넘는 tool 결과는 원문을 디스크에 두고 요약본만 컨텍스트에 넣는다. 나중에 원문이 필요하면 expand로 꺼낸다. 실패한 명령의 출력은 아예 압축 대상에서 빠진다. 에러 메시지를 요약해 버리면 원인을 못 찾기 때문이다. 압축 규칙은 command-filters.toml로 늘리거나 빼고, 보고 싶지 않은 파일은 .contextignore로 제외한다.

세션이 길어져 압축이 일어나기 직전에는 체크포인트를 남긴다. 결정 사항과 제약이 그 안에 들어가고, 압축 뒤에 resume-lean으로 이어받으면 빈 세션에서 다시 시작하는 것보다 훨씬 적은 토큰으로 복귀한다. 저장소는 30일 스냅샷에서 회수한 토큰을 약 390만 개로 적어 두었는데, 이 역시 자체 측정치다.

라이선스가 그은 선

PolyForm Noncommercial 1.0.0이다. 흔히 말하는 OSI 오픈소스가 아니라 소스 공개이고, 개인·연구·교육 용도는 그대로 무료다. 문제는 회사에서 쓸 때다. 세션 로그와 메모리를 읽는 도구라 소스를 공개해 둔 것이고, 상업적 사용은 별도 계약이 원칙이다.

예외가 하나 있다. 직원 5명 미만이면서 월 매출 2만 달러 미만인 회사는 LICENSE-SMALL-BUSINESS.md로 상용 라이선스를 무료로 받는다. 두 조건을 모두 만족해야 하고, 모회사·자회사까지 합쳐서 센다. 큰 회사 안의 작은 팀은 여기에 해당하지 않는다.

도입 전 체크리스트

1. 하네스: Claude Code나 Codex를 쓰는지 본다. 다른 도구만 쓴다면 얻는 게 적다.

2. 라이선스: 회사가 5인·월 2만 달러 선 아래인지 확인한다.

3. 데이터: 세션 로그와 메모리를 읽는다. 로컬에서만 돌지만, 소스가 공개돼 있으니 직접 확인할 수 있다.

4. 되돌리기: 언인스톨은 자기가 설치한 것만 지운다. 기존 훅과 설정은 그대로 둔다.

정리

체감이 큰 쪽은 Claude Code를 하루 종일 켜 두는 사람이다. 세션이 짧으면 압축이 일어날 일도 적고, 자동으로 도는 기능도 별로 없다. 반대로 긴 작업을 여러 세션에 걸쳐 이어 붙인다면 체크포인트와 expand만으로도 설치한 값을 한다.

문서가 도구 자체보다 친절한 편이라, README의 All Commands 표를 한 번 훑고 필요한 명령만 골라 쓰면 된다. 처음부터 전부 켜 둘 이유는 없다.
