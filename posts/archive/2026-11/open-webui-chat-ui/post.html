사내에서 로컬 LLM을 도입하면 반드시 다음 질문이 나옵니다. "직원들이 쓸 화면은요?" Ollama는 API만 주고 UI는 없으니, 각자 터미널로 붙든지 ChatGPT 클론을 따로 띄우든지 해야 합니다. 그런데 이 "화면"을 만드는 데 프론트엔드 인력이 들어가면 프로젝트가 늘어집니다.

Open WebUI는 이 문제를 정면으로 해결한 셀프 호스팅 플랫폼입니다. GitHub 별 15만 개를 넘겼고, README 스스로를 "오프라인에서 완전히 돌아가는 AI의 집"이라고 부릅니다.

채팅 화면을 직접 만드는 비용

LLM 백엔드와 달리 채팅 UI는 겉보기보다 할 일이 많습니다. 스트리밍 응답, 마크다운 렌더링, 대화 히스토리, 사용자별 권한, 모델 선택 드롭다운까지 — 기본 채팅 하나에도 상당한 작업이 붙습니다.

여기에 사내 요구사항이 얹히면 더 커집니다. 자료를 올려 근거 기반으로 답하게 하는 RAG, 팀원이 공유하는 프롬프트 라이브러리, 로그와 사용량 관리까지. 이걸 직접 만들면 본업인 모델 도입이 UI 개발로 변질됩니다.

그래서 많은 팀이 ChatGPT 웹 UI를 그대로 쓰거나, 각자 터미널 도구를 섞어 씁니다. 둘 다 사내 정책과 사용성 면에서 반쪽짜리죠.

Open WebUI가 대신하는 것

Open WebUI는 ChatGPT와 거의 같은 사용 경험을 주는 웹 UI에, 셀프 호스팅에 필요한 것들을 얹은 플랫폼입니다.

  • 멀티 모델 연결 — Ollama는 물론 OpenAI 호환 API면 무엇이든 붙습니다
  • 완전 오프라인 동작 — 로컬 모델만 쓰면 외부 네트워크 없이 돌아갑니다
  • 확장 구조 — 함수·파이프라인·지식베이스 같은 플러그인 생태계
  • 팀 기능 — 사용자 관리와 권한, 공유 자원
README의 표현 그대로 "a home for AI"입니다. 모델을 바꿔도 UI는 그대로 씁니다.

주의할 점이 하나 있습니다. 라이선스가 MIT가 아니라 자체 Open WebUI License입니다. 소스 수정·재배포는 되지만 Open WebUI 브랜딩을 유지해야 하는 조건이 붙어 있습니다.

설치: pip 한 줄

Python 3.12가 필요합니다.

pip install open-webui
open-webui serve

실행 후 http://localhost:8080을 열면 첫 화면이 뜹니다. 최초 실행 시 관리자 계정을 만들고, 이후 팀원을 초대하는 구조입니다.

개발 환경이나 임시 테스트라면 이 방법이 가장 빠릅니다. 설치 자체는 1분도 안 걸립니다.

Docker와 데스크톱 앱

서버에 상시 띄울 거라면 Docker가 정석입니다. 이미지는 용도별로 태그가 나뉩니다.

docker run -d -p 3000:8080 --add-host=host.docker.internal:host-gateway -v open-webui:/app/backend/data --name open-webui --restart always ghcr.io/open-webui/open-webui:main
이미지 태그용도
:main표준, 로컬 AI 의존성 포함
:slim경량, 임베딩·문서추출·음성을 외부 서비스로
:cudaCUDA 가속 포함
:ollamaOllama 내장
:dev개발 빌드

개인용으로는 데스크톱 앱도 있습니다. macOS·Windows·Linux용 네이티브 앱이 따로 배포되고 있어서, 서버 없이 내 PC에서만 쓸 거면 이게 제일 간단합니다.

Ollama에 붙이는 설정

가장 흔한 조합은 Ollama + Open WebUI입니다. Ollama가 모델을 돌리고, Open WebUI가 화면을 담당합니다.

Ollama가 같은 서버에 있으면 자동으로 잡히고, 다른 서버라면 환경변수로 주소를 지정합니다.

-e OLLAMA_BASE_URL=http://your-ollama-server:11434

GPU를 쓰려면 --gpus all을 붙입니다(Nvidia Container Toolkit 필요). 클라우드 모델도 같이 쓰려면 OPENAI_API_KEY를 넣으면 됩니다 — 로컬과 클라우드를 한 화면에서 오갈 수 있는 게 이 플랫폼의 묘미입니다.

오프라인과 지식베이스

사내 보안이 까다로운 환경에서는 완전 오프라인 구성이 가능합니다. Hugging Face 다운로드를 끄는 옵션이 있습니다.

-e HF_HUB_OFFLINE=1

문서 기반 질의응답은 지식베이스(Knowledge Base) 기능으로 해결합니다. 회사 문서를 올려두면 검색해 근거와 함께 답하는 RAG 흐름을 UI에서 바로 쓸 수 있습니다. 외부 동기화가 필요하면 생태계의 oikb가 폴더·레포·버킷을 지식베이스로 증분 동기화해 줍니다.

확장 생태계

README가 소개하는 생태계 프로젝트들이 이 플랫폼의 방향을 보여줍니다.

  • Open Terminal — Open WebUI를 에이전트 하네스로 확장하는 액션 레이어. 엔터프라이즈용 오케스트레이션도 포함
  • oikb (Knowledge Base Sync) — 폴더·레포·버킷·위키를 지식베이스로 증분 동기화
  • Open WebUI Computer — 브라우저에서 파일·에디터·터미널·git까지 여는 원격 데스크톱

셀프 호스팅 채팅 화면을 넘어 "회사의 AI 작업 공간"으로 가려는 그림입니다.

사내 도입 시 확인할 것

  • 라이선스 — Open WebUI License는 브랜딩 유지 조건이 있습니다. 재배포·재판매 계획이 있다면 LICENSE_HISTORY까지 읽어야 합니다
  • 데이터 위치 — open-webui 볼륨에 대화와 업로드 파일이 저장됩니다. 백업 정책이 필요합니다
  • 업데이트 — 공식 업데이트 가이드가 따로 있으니 버전업 절차를 미리 정해 두세요
  • 연결 보안 — 사내망에만 바인딩하고, 외부 노출이 필요하면 리버스 프록시+인증을 앞에 두세요

한계와 주의

  • 자체 라이선스 — MIT가 아니므로 상용 재포장에는 제약이 있습니다
  • 리소스 — 문서 임베딩·STT 같은 기능이 붙으면 서버 사양 요구가 올라갑니다
  • 모델 성능 — UI가 아무리 좋아도 로컬 모델의 답변 품질이 상한선입니다
  • 초기 설정 — 사용자·권한·모델 연결을 조직 규모에 맞게 잡는 데 시간이 듭니다

정리

Open WebUI는 "직원용 ChatGPT를 사내에 띄우는" 가장 빠른 길입니다. pip 한 줄이나 docker run 한 줄이면 채팅 화면이 서고, Ollama든 OpenAI든 모델은 마음대로 바꿀 수 있습니다. 셀프 호스팅 LLM 도입의 마지막 퍼즐이라고 보면 됩니다. 다만 라이선스가 MIT가 아니라는 점만 도입 검토 때 꼭 확인하세요.
