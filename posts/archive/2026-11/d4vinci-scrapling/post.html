웹에서 데이터를 긁는 일은 대개 두 갈래로 나뉩니다. 정적 페이지는 HTTP 요청으로 빠르게 가져오고, 자바스크립트로 그려지는 화면은 브라우저를 띄워야 합니다. 여기서 도구가 하나씩 늘어납니다.

Scrapling은 그 두 갈래를 한 라이브러리로 묶은 파이썬 프레임워크입니다. HTTP 요청, 스텔스 브라우저, 파싱, 동시 크롤링이 한 패키지에 들어 있고, MCP 서버와 에이전트 스킬까지 같이 제공합니다. 설치부터 첫 수집까지 순서대로 정리했습니다.

핵심 특징 3가지

README가 내세우는 기능은 세 덩어리로 정리됩니다. 가져오기, 파싱, 크롤링입니다.

  • 가져오기 — 빠른 HTTP 요청, 스텔스 브라우저, 자바스크립트 렌더링, Cloudflare Turnstile·Interstitial 대응, 세션 유지, 백그라운드 API 응답 캡처를 한 인터페이스에서 처리합니다.
  • 파싱 — CSS, XPath, 텍스트, 정규식 검색을 지원합니다. 요소가 바뀌어도 따라가는 adaptive element tracking과 비슷한 요소 묶음 매칭이 들어 있고, 결과를 마크다운으로 바로 뽑을 수 있습니다.
  • 크롤링 — 재사용 세션, 프록시 로테이션, 자동 재시도, 일시정지와 재개, 데이터 내보내기가 기본으로 붙습니다.

세 덩어리가 한 패키지에 있다는 점이 핵심입니다. 정적 페이지와 동적 페이지를 같은 코드베이스에서 다룰 수 있어서, 사이트마다 도구를 갈아끼우지 않아도 됩니다.

설치와 빠른 실행

파이썬 3.10 이상이 필요합니다. 기본 설치는 한 줄입니다.

pip install scrapling

브라우저 렌더링까지 쓸 때는 설치 옵션이 따로 있습니다. 정확한 옵션은 문서의 Installation 절을 확인하는 편이 안전합니다. 도커 이미지도 올라와 있어서 컨테이너로 띄울 수 있습니다.

docker pull pyd4vinci/scrapling

실전 활용 시나리오

처음에는 한 페이지에서 시작합니다. 목록 페이지 하나를 잡고 상세로 넓히는 순서가 안전합니다.

  • 1단계 — 설치하고 파이썬 버전이 3.10 이상인지 확인합니다.
  • 2단계 — 정적 페이지는 HTTP 요청으로 먼저 시도합니다. 응답에 데이터가 비어 있을 때만 브라우저 렌더링으로 넘어갑니다.
  • 3단계 — CSS나 XPath로 원하는 요소를 잡고, 마크다운 출력으로 결과를 눈으로 확인합니다.
  • 4단계 — 목록에서 상세로 넓히면서 세션 재사용과 재시도를 켭니다. 프록시는 차단이 확인된 뒤에 붙입니다.

사이트가 자바스크립트로 API를 호출한다면 화면을 긁는 대신 그 API 응답을 잡는 쪽이 유지보수에 유리합니다. README도 이 방식을 기능으로 소개합니다.

AI 에이전트에 붙이는 두 가지 길

요즘 이 라이브러리의 쓰임은 크롤러보다 에이전트 쪽에 가깝습니다. README는 두 갈래를 제공합니다.

  • MCP 서버 — Claude나 Cursor 같은 에이전트가 HTTP 요청, 브라우저 조작, 스크린샷, 저장된 로그인 상태, 백그라운드 API 응답을 도구로 씁니다. 모델에 보내는 내용을 줄이고 광고를 걸러내는 장치도 들어 있습니다. 원격 브라우저는 CDP와 HTTP 전송으로 붙이고 인증 옵션을 받습니다.
  • 에이전트 스킬 — 코딩 에이전트에게 이 라이브러리 전체를 가르치는 설치형 스킬입니다. 에이전트가 API를 추측하지 않고 현재 버전에 맞는 코드를 쓰게 하는 것이 목적입니다.

직접 스크립트를 쓰는 사람에게는 첫 번째가, 에이전트에게 크롤러 코드를 맡기는 사람에게는 두 번째가 쓸모 있습니다.

직접 쓰기 전 알면 좋은 점

  • 안티봇 대응은 양날 — Cloudflare 처리를 기능으로 내세우지만, 대상 사이트 약관과 robots 정책을 먼저 확인해야 합니다.
  • 브라우저 의존 — 스텔스 브라우저는 별도 설치와 자원을 씁니다. 서버에 올릴 때 메모리 사용량을 먼저 재 보세요.
  • 셀렉터 유지보수 — adaptive tracking이 도움은 되지만 사이트 구조가 바뀌면 결국 손봐야 합니다.
  • MCP 서버 보안 — 원격 브라우저와 로그인 상태를 다루므로 인증 옵션과 권한 범위를 최소로 두세요.
README 스스로 "BEST"를 붙일 만큼 기능 폭이 넓습니다. 폭이 넓다는 건 설정할 것이 많다는 뜻이기도 합니다.

누구에게 필요한가

파이썬으로 수집 파이프라인을 만드는 사람과, 에이전트에 웹 접근을 붙이려는 사람에게 맞습니다.

  • 정적 페이지와 동적 페이지를 한 코드로 다루고 싶은 개발자
  • Claude나 Cursor에 웹 수집 도구를 물려 주려는 사람
  • 프록시 로테이션과 재시도를 직접 구현하지 않으려는 팀

반대로 한 번 긁고 마는 일회성 작업이거나, 브라우저를 띄울 자원이 없는 환경이라면 가벼운 HTTP 클라이언트로 충분합니다.

정리

Scrapling은 수집에 필요한 네 가지를 한 패키지에 모은 프레임워크입니다. 설치가 한 줄이고, 정적 페이지에서 시작해 브라우저 렌더링으로 넓히는 순서가 자연스럽습니다.

에이전트에 붙일 생각이라면 MCP 서버부터 확인해 보세요. 코드를 쓰는 쪽이라면 에이전트 스킬을 설치해 두면 API를 잘못 추측하는 일이 줄어듭니다.
