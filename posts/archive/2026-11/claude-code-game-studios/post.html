문제 제기

인디 게임을 혼자 만들려는 사람에게 Claude Code 한 세션은 마법처럼 보입니다. "게임 만들어 줘"라고 치면 기획서도 나오고 코드도 나옵니다. 그런데 프로젝트가 커지는 순간 무너집니다. 기획과 구현과 아트가 한 덩어리로 섞이고, 누가 무엇을 결정했는지 사라지고, 검증 없이 "완료"가 선언됩니다.

문제는 모델이 아니라 구조입니다. 실제 게임 스튜디오가 디렉터, 부서 리드, 전문직으로 나뉘듯, AI 세션도 역할이 나뉘어야 협업이 됩니다.

에이전트 오토파일럿이 아니라, 실제 스튜디오 위계를 흉내 낸 게임 개발 스튜디오 템플릿입니다.

무엇인가

Claude-Code-Game-Studios(약칭 CCGS)는 Claude Code를 게임 개발 스튜디오로 바꾸는 템플릿 저장소입니다. GitHub 별 3만 6천 개, 포크 4천 7백 개, MIT 라이선스, 퍼블릭 템플릿으로 제공됩니다.

구성은 압도적입니다. 49개 전문 서브에이전트, 74개 슬래시 스킬, 15개 이벤트 훅, 경로별 코딩 규칙 14개, 문서 템플릿 62개가 들어 있습니다. 에이전트는 실제 스튜디오처럼 세 계층으로 조직됩니다.

중요 — 이건 자율 개발 시스템이 아닙니다. 에이전트는 질문하고, 선택지를 보여 주고, 당신이 결정하고, 초안을 보여 주고, 승인받은 것만 씁니다. 구조와 전문성은 주되 자율성은 주지 않는 설계입니다.

스튜디오 위계

49개 에이전트는 세 단계로 나뉩니다. 디렉터 3명이 최상위고, 부서 리드 9명이 그 아래, 전문가 30여 명이 밑에 있습니다.

계층 역할
Tier 1 — 디렉터 creative-director, technical-director, producer
Tier 2 — 부서 리드 game-designer, lead-programmer, art-director, audio-director, narrative-director, qa-lead, release-manager, localization-lead
Tier 3 — 전문가 gameplay/engine/ai/network/tools/ui-programmer, level/economy/systems-designer, technical-artist, sound-designer, writer, ux-designer, performance-analyst, security-engineer, qa-tester 등

각 에이전트는 frontmatter에 모델을 선언합니다. 디렉터 3명은 Opus를 요청하고, lead-programmer와 전문가 15명은 Sonnet을 지정하며, 나머지 30명은 세션의 모델을 그대로 물려받습니다. 계층은 과금 계획이 아니라 역할의 서열로 읽으면 됩니다.

엔진별 전문가 세트도 따로 있습니다. Godot 4는 godot-specialist 아래 GDScript·셰이더·GDExtension, Unity는 DOTS/ECS·셰이더/VFX·Addressables·UI Toolkit, Unreal Engine 5는 GAS·Blueprints·Replication·UMG/CommonUI로 나뉩니다. 프로젝트 엔진에 맞는 세트만 쓰면 됩니다.

에이전트 협업 규칙

협업은 세 가지 원칙으로 묶여 있습니다.

  • 수직 위임 — 디렉터가 리드에게, 리드가 전문가에게 위임합니다.
  • 수평 협의 — 같은 계층끼리는 상의할 수 있지만, 구속력 있는 부서 간 결정은 못 합니다.
  • 충돌 에스컬레이션 — 의견이 갈리면 공통 상위(디자인은 creative-director, 기술은 technical-director)로 올라갑니다. 부서를 넘는 변경은 producer가 조정합니다.

도메인 경계도 명확합니다. 자기 영역 밖의 파일은 명시적 위임 없이 수정하지 않습니다. 커밋 전·푸시 전·에셋 변경·디자인 문서 읽기와 쓰기·세션 시작과 종료에 걸리는 15개 훅이 이 규칙들을 자동으로 검증합니다.

rigor 설정이 핵심

이 템플릿의 가장 중요한 설정은 project.yaml의 modes.rigor입니다. minimal, standard, full 세 단계가 GDD 필수 섹션 수, 문서 밀도, QA 수준, 스토리 단위, 리뷰 모드, 팀 규모 여섯 개 노브를 한 번에 조절합니다.

README는 같은 브리프로 네 가지 게임을 만들어 문서 수를 셌습니다. 게임 코드 첫 줄 전에 쓰인 문서가 minimal은 1개(한 페이지 브리프), standard는 30개(58분 소요)였습니다. 전부 실행되고 테스트되는 게임이었지만, 블라인드 리뷰와 실제 플레이테스트에서 standard 빌드가 꼴찌로 밀렸습니다. 문서 29개가 더 산 건 추적성이었지 더 나은 게임이 아니었습니다.

그래서 minimal이 기본값입니다. 무거운 단계는 더 나은 결과 없이 코드까지 가는 비용만 키우기 때문입니다. 프로젝트가 커지면 /settings 한 번으로 올리면 되고, 특정 시스템만 높이려면 system_overrides가 있습니다.

검증의 절반은 눈으로 한다 — 플레이어가 보는 걸 바꾸는 스토리는 게임을 실제로 실행하고, 화면을 보고, 스크린샷을 production/qa/evidence/에 남길 때까지 닫히지 않습니다. 테스트 통과는 화면 밖으로 그려진 메뉴에 대해 아무 말도 하지 않습니다.

설치와 시작

필요한 건 Git, Claude Code, Python 3, Bash입니다. Python이 project.yaml을 읽어 모든 스킬과 훅에 설정을 먹이므로, 없으면 모든 설정이 조용히 기본값으로 떨어집니다. jq는 권장이지만 없어도 훅이 실패하지 않고 검증만 빠집니다.

git clone https://github.com/Donchitos/Claude-Code-Game-Studios.git my-game
cd my-game
claude

중요한 게 하나 있습니다. 반드시 프로젝트 루트(CLAUDE.md와 project.yaml이 있는 폴더)에서 claude를 시작해야 합니다. src/ 같은 하위 폴더에서 시작하면 프로젝트 훅과 deny 규칙, ask-first 권한 모드가 전부 빠집니다.

세션 안에서는 /start가 시작점입니다. 아이디어가 없는지, 막연한지, 설계가 잡혔는지, 기존 작업이 있는지 물어보고 맞는 워크플로로 안내합니다. 이미 엔진을 정했으면 /setup-engine godot 4.7처럼 바로 들어가도 됩니다.

슬래시 명령은 74개입니다. /brainstorm, /design-system, /create-epics, /create-stories, /dev-story, /story-done 같은 스프린트 흐름부터 /balance-check, /security-audit, /release-checklist, /hotfix까지 게임 개발 전 주기를 덮습니다.

커스터마이즈와 자체 검증

CCGS는 고치라고 있는 템플릿입니다. 저장소 안의 studio-tests/가 74개 스킬과 49개 에이전트를 카탈로그화해 두고, 카테고리별 품질 루브릭과 행동 스펙을 제공합니다.

/skill-test static [name]     # 구조 린터 — 7개 규정 검사
/skill-test category [name]   # 카테고리별 품질 루브릭
/skill-test spec [name]       # 행동 스펙 단언
/skill-test audit             # 커버리지 리포트
/skill-improve [name]         # 테스트-수정-재테스트 루프

이건 프레임워크 자체를 검사하는 도구이지 게임을 검사하는 게 아닙니다. 게임 테스트는 tests/에 따로 있습니다.

한계와 주의

규모에 속지 마세요. 49개 에이전트와 74개 스킬은 문서와 절차의 무게입니다. standard 이상으로 올리면 문서 작업이 게임 코드보다 커질 수 있고, README 스스로 그 비용을 측정해 보여 줬습니다. 혼자 만드는 게임 잼이면 minimal로 시작하는 게 맞습니다.

Python과 Bash 의존도 실질적입니다. 훅이 "실패해도 조용히 넘어가는" 설계라, 도구가 없으면 검증 없이 진행될 수 있습니다. 커밋에 데이터 JSON이 스테이징되면 Python이 없을 때 훅이 커밋 자체를 막는 게 유일한 예외입니다. Claude Code 세션 기준으로 설계됐다는 점도 감안해야 합니다. 다른 에이전트 호스트로 옮기려면 어댑터 작업이 필요합니다.

도입 전 체크리스트

확인할 것 4가지

✓ 시작 위치 — 프로젝트 루트에서 claude 실행(하위 폴더면 훅·규칙 누락)

✓ rigor — 혼자면 minimal, 커지면 /settings로 조정

✓ 도구 — Python 3 필수, jq 권장, Git for Windows의 Bash 사용

✓ 검증 — 스토리 완료는 실행·스크린샷 증거가 있어야 함

정리

CCGS는 "AI가 게임을 만드는가"가 아니라 "AI 팀이 게임을 만드는 구조를 어떻게 짜는가"에 대한 답입니다. 디렉터-리드-전문가 위계, 부서 간 위임 규칙, 그리고 문서가 많을수록 게임이 나빠진다는 스스로의 측정까지 담고 있습니다.

오늘 해 볼 일은 clone해서 /start를 쳐 보는 겁니다. 아이디어가 없는 상태에서 어디로 안내하는지 보면, 이 템플릿이 실제로 어디까지 데려다주는지 감이 잡힙니다.
