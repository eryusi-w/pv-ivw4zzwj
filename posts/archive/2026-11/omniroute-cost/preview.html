OmniRoute로 LLM 비용과 한도 관리하기

#OmniRoute#LLM#게이트웨이#라우팅#쿼터#비용절감#API키#오픈소스#개발도구#모니터링

코딩 에이전트를 쓰다 보면 API 비용이 은근히 커집니다. Claude Code든 Codex든 호출량이 늘면 월 청구서가 무시 못 할 수준이 되죠. 그런데 무료 티어를 가진 프로바이더가 수십 개인데, 각각 따로 가입하고 키를 관리하고 한도를 추적하는 건 사실상 불가능에 가깝습니다.

OmniRoute는 이 문제를 "로컬 게이트웨이 하나를 두는 방식"으로 해결합니다. 여러 AI 프로바이더를 하나의 엔드포인트 뒤에 묶어, 도구는 그대로 두고 비용과 한도만 관리하는 구조입니다. GitHub 별 8.5만 개, MIT입니다.

OmniRoute는 무엇인가

README의 표현 그대로 "Free AI Gateway"입니다. Claude Code, Codex, Cursor, Cline, Copilot, Antigravity 같은 AI 도구들이 쓰는 API 호출을 가로채서, 연결된 프로바이더 중 가장 적합한 곳으로 라우팅합니다.

지원 규모가 큽니다. README 기준 380개 프로바이더, 150개 이상의 무료 티어를 카탈로그로 관리하고, 20가지 라우팅 전략을 제공합니다. 무료 티어를 합산하면 월 약 16억 토큰 규모라고 주장하지만, 이 숫자는 공유 풀 중복을 제거한 보수적 계산이며 2주마다 재감사됩니다.

중요한 전제: 이건 "OmniRoute가 토큰을 주는" 게 아니라, 당신이 각 프로바이더에 가입해 키를 연결하는 구조입니다. 무료 티어의 한도·조건은 각 프로바이더가 정합니다.

라우팅 계층 구조

OmniRoute는 프록시가 아니라 라우팅 계층입니다. 클라이언트는 localhost:20128/v1 같은 단일 엔드포인트만 보고, 뒤에서 OmniRoute가 어떤 프로바이더로 보낼지 결정합니다.

모델명에 auto를 쓰면 사용 가능한 연결 중 알아서 고릅니다. 특정 모델을 지정하거나, Combos라는 라우팅 전략으로 우선순위·폴백 체인을 직접 정의할 수도 있습니다.

쿼터 인식 스케줄링(Quota-Share)도 있습니다. 어떤 프로바이더의 한도가 얼마 남았는지 실시간으로 보고, 한도가 찬 곳은 자동으로 건너뜁니다.

설치와 첫 실행

npm 글로벌 설치가 가장 빠릅니다.

npm install -g omniroute
omniroute

또는 Docker, Bun, 소스 빌드, 심지어 안드로이드 Termux에서도 돌릴 수 있습니다. 데스크톱은 Electron 앱과 macOS 메뉴바 앱(OmniRouteTray)도 있습니다.

# Docker 예시
docker run -d -p 20128:20128 diegosouzapw/omniroute

설치 후 대시보드에서 프로바이더를 연결하고, 발급받은 OmniRoute API 키를 클라이언트에 설정하면 됩니다.

클라이언트 연결

연결은 두 가지 방식입니다.

  • OpenAI 호환 엔드포인트 — http://localhost:20128/v1을 base URL로 지정
  • 도구별 프리셋 — Claude Code, Codex, Cursor 등에 맞는 설정 가이드 제공

VS Code Copilot Chat에는 OmniCopilot 확장으로 모든 OmniRoute 모델을 Copilot Chat 피커에서 바로 쓸 수 있습니다.

토큰 압축: 15~95% 절감

OmniRoute의 또 다른 축이 RTK + Caveman 압축입니다. 프롬프트와 응답을 전송 전에 압축해 토큰을 아낍니다. README는 평균 약 89%, 최대 95% 절감을 주장합니다.

무료 티어 한도가 빠듯한 환경에서는 이 압축이 실질적인 의미를 가집니다. 같은 작업을 더 적은 토큰으로 처리하니 한도가 오래 갑니다.

쿼터 대시보드 읽는 법

/dashboard/free-tiers에서 각 프로바이더의 무료 티어 현황을 볼 수 있습니다. 남은 쿼터, 사용량, 한도 리셋 주기까지 표시됩니다.

README가 강조하는 점: 카탈로그는 2주마다 재감사되고, 약관상 위험이 있는 프로바이더 12개는 "avoid"로 표시돼 자동 라우팅에서 제외됩니다. "무료"가 무조건 좋은 게 아니라는 걸 스스로 인정하는 구조입니다.

고급 기능

단순 프록시를 넘어선 기능들이 있습니다.

  • Remote mode — VPS에 설치하고 scoped token으로 원격 제어
  • MITM/TPROXY — 프록시 환경변수를 무시하는 CLI도 가로채는 투명 복호화
  • Headless mode — serve --headless로 서버 전용 운영
  • MCP·A2A — 다른 에이전트와의 연동 프로토콜 지원
  • 모델 발견 API — /v1/models/query로 사용 가능 모델 조회

실전 활용 시나리오

실제로 효과가 나는 경우는 정해져 있습니다.

  • 개인 개발자 — 여러 무료 티어를 조합해 코딩 에이전트 비용을 사실상 0에 가깝게
  • 소규모 팀 — 공용 게이트웨이로 API 키를 중앙 관리하고 사용량을 가시화
  • 실험·프로토타이핑 — 모델을 마음껏 바꿔 비교하되 비용 부담 없이

반대로 프로덕션 서비스의 안정성이 중요한 경우에는 무료 티어의 변동성이 오히려 리스크가 됩니다. 개발·실험용으로 쓰고, 운영은 유료 API로 분리하는 게 안전합니다.

한계와 주의

  • 약관 리스크 — 무료 티어를 API 게이트웨이로 우회하는 건 각 프로바이더 약관 위반일 수 있습니다. "avoid" 표시를 무시하지 마세요
  • 불안정성 — 무료 티어는 언제든 바뀌거나 사라집니다. 카탈로그가 2주마다 바뀌는 이유입니다
  • 지연 — 무료 티어는 속도 제한이 있어 응답이 느릴 수 있습니다
  • 품질 편차 — 한도가 차면 더 낮은 모델로 폴백돼 품질이 떨어질 수 있습니다
  • 자체 호스팅 — API 키를 로컬에 저장하므로 보안 관리가 필요합니다

정리

OmniRoute는 "여러 무료 LLM을 하나의 엔드포인트로"라는 단순한 아이디어를, 라우팅 전략·쿼터 관리·토큰 압축까지 갖춘 게이트웨이로 키웠습니다. API 비용을 줄이고 싶거나 여러 무료 티어를 효율적으로 쓰고 싶은 개발자에게 유용합니다. 다만 무료 티어의 약관 리스크와 불안정성을 감안해, 보조 수단으로 쓰는 게 현실적입니다.
