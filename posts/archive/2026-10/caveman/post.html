AI 스타일 설정, caveman

Claude Code나 Codex 같은 코딩 도우를 쓰다 보면 종종 답변이 길게 느껴진다. "좋은 질문이야", "확인해 보겠어", "처음과 같이 문장" 같은 문구가 매번 붙고, 작성 필요 없이 줄이는 방법만 있는 경우가 많다.

불필요하게 많이 토큰을 쓰면 비용이 된다. API 호출 시 출력이 클수록 과금이 되고, 구독료도 빨리 든다. 그래서 "AI가 좀 더 말하게"라는 필요가 꾸준히 있다.

why use many token when few token do trick

문장을 줄여야 한다면 caveman 스타일이다. 이름에서 알 수 있듯 "짧게 말하기"가 핵심 목적이다. GitHub 스타 10개 이상인 로켓트 프로젝트답게 실제로도 "간결하게 말하기"에 특화되어 있다.

caveman의 핵심 기능

caveman은 문체를 자동으로 다듬어 준다. 핵심은 "짧게, 적게"다. 코드를 정확히,뇌에 남지 않게 하되 가장 중요한 것은 문체 변화에 있다.

강도 조절이 가능하다. 기본 /caveman은 20%, 줄인 /ultracave는 14%, 고전 문체(문어체로 설명할 때 사용)인 /megacave는 13%다. 가장 실용적인 모드는 기본 모드다.

5가지 주요 기능을 제공한다.

기능 기능 설명 README 측정
Say less짧게, 코드 실행 여부63 vs 20 (약 1/3)
Read less로그·JSON·CSV·스페이스 출력 축소기능 사용 시 크기 33.2% 감소
Auto요청마다 모델 추론 강도 자동 선택비용 54% 감소 (중간 결과)
Blocks코드들이 스크립트 안으로 해제 가능파일 크기 397 vs 76 (약 1/5)
Waste fixes불필요한 부분을 찾아 수정직접 측정 중
Browse웹 페이지 축소 기능페이지 크기 129.8% 감소

전체 기능 사용이 필요할 땐 Auto만 켜면 된다. 나머지 무료로 제공되지 않고 PC에서 API 키나 Claude Pro/Max 로그인 없이 작동한다.

caveman 사용법

전체 기능을 실행하려면 Node.js 22.13 이상이 필요하다. macOS, Linux, Windows 모두 지원한다. 실행하면 PC에 설치된 도구의 로그를 찾아 보여주며, Enter를 누르면 사용법을 보여준다.

# 최신 버전 설치
npx @caveman-ai/cli@latest

# 켜진 기능 및 진단 확인
caveman status        # 켜진 기능 확인 및 진단 출력

# 기능 끄기
caveman off browse    # 기능 비활성화

# 진단 모드
caveman doctor        # 문제 파악 후 해결 방법과 함께 출력

Codex, Gemini CLI, OpenCode 등에도 30개 이상 통합된다. 실행하면 바로 caveman 스타일로 변환해 주는지를 보여주고, Enter를 누르면 사용법을 보여준다.

# 스타일 추가
npx skills add JuliusBrussee/caveman -g

# Codex에서 /caveman         # Codex에서 $caveman
/ultracave        # 더 짧게
stop caveman      # 이전 말투로 복구

문체를 줄이는 핵심 규칙

caveman 스타일은 "문법이 잘못된 것이 아니다"라는 점에 주목한다. 문체만 바꾸는 규칙이다. 좀 더 짧게 말하게 해주는 것이다. ASD-STE100 기반으로 문장 20% 정도를 줄일 수 있도록 설계되었다.

무엇을 빼야 하는지도 명확하지 않다. 관리자 빠질 때마다 not, never, only 같은 부정어는 가급적 피하고, 단어 위치는 정확하게 유지한다. 코드, 명령어 경로, 오류 메시지 등도 바꾸지 않는다. 보안 경고, 시스템 메시지는 그대로 두면서 질문 내용만 짧게 만든다.

추가 규칙도 있다. 보안 경고, 시스템 로그, 사용량 등은 그대로 두면서 질문의 문장만 짧게 만든다. Adobe 제품군에서 쓰는 질문도 바로 문체 변환된다.

Read less로 출력 줄이기

caveman 기능 사용 시 비용이 줄어든다. 출력 토큰에서 옵션한다. 로그, JSON, CSV 파일 등이 기본값보다 훨씬 빠르게 입력된다. Read less는 그런 출력 옵션 모델에 따라 다르다. Claude Code 기능에서 측정했을 때 전체 출력 크기 33.2%가 18개 질문 모두 정확히 맞아떨어졌다. 다만 HTML은 여전히 축소되지 않았거나 9.9%만 줄어들었다. 기본 파일 경우 바로 꺼내 쓴다.

65%는 숫자 조작일까?

핵심 주장은 "큰 65% 감소"라고 하지만 숫자는 구체적이지 않다. "간결하게 하다(Answer concisely)"는 더 줄인다. /caveman 중앙값 3%, /ultracave 35% 줄어들었다. 게다가 규칙 본체가 1,160 크기 출력 감소 측정이 보고되었다.

비슷한 실험 결과도 있다. 코딩 과제 86개에서 출력 크기 8.5% 감소가 측정된 보고가 있다. 300자씩 긴 질문을 적은 질문 질문? 경험에서 전체 비용 0.06%만 감소했다. 출력 감소의 주요 원인은 캐시 읽기일 수 있다. 그래서 비용 절감의 핵심은 출력보다 기능 Read less에 있다.

입장 확인하기

caveman은 "AI 스타일 기본적으로 말하게"면 이득이다. 비용 절감 효과가 있다고 하지만 출력보다 기능 Read less가 핵심이고, 과금 방식에 따라 달라질 수 있다. 짧 Q&A를 자주 하면 규칙 본체 비용 감소 효과가 커질 수도 있다. 하지만 과금 방식에 따라 다르다. 짧은 Q&A보다 긴 Q&A 비교 시 더 큰 효과를 볼 수 있다. 결국 실제 사용해 보고 직접 비교해 보는 것이 좋다. caveman trial 명령으로 A/B 비교를 직접 해볼 수 있다.

총평

caveman은 "AI가 기본적으로 말하게" 출발점이다. 비용 절감 효과가 있지만 출력보다 기능 Read less가 핵심이고, 과금 방식에 따라 다르다. 비용 절감 체감은 빠르지만, 실제 사용해 보고 직접 비교해보는 것을 추천한다.
