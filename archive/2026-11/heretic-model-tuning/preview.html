Heretic으로 모델 성향을 바꾸는 법

#Heretic#AGPL#모델수정#파이토치#파이썬#로컬실행#재현성#플러그인#연구#라이선스

문제 제기: 모델을 다시 학습시키지 않고 고치는 일

로컬에서 돌리는 오픈 모델은 성향이 마음에 안 들 때가 많습니다. 거절이 너무 많거나, 칭찬이 지나치거나, 슬롭(형식적인 빈말)이 지나치게 많습니다. 이런 걸 고치려면 보통 파인튜닝이 필요한데, 그건 GPU 수십 장짜리 작업입니다.

그런데 학습 없이 가중치를 직접 조정해서 행동을 바꾸는 방법이 있습니다. Heretic은 그걸 "오후 한 나절, 게이밍 PC에서" 할 수 있게 만든 도구입니다.

비싼 학습 대신, 대비되는 예시 프롬프트와 채점기로 가중치를 수학적으로 조정합니다. Heretic의 방식입니다.

무엇인가: Heretic

p-e-w/heretic은 학습 없는 언어 모델 수정(training-free LM modification) 도구입니다. GitHub 별 4만 개, 라이선스는 AGPL-3.0입니다.

README가 내세우는 용도는 이렇습니다: 검열 제거(기본값), 슬롭 감소, 유머 감소, 아첨(sycophancy) 감소, 감정 정렬 변경 등. "언어 모델이 내부적으로 어떻게 작동하는지 이해할 필요가 없다"고 강조하는 게 특징입니다. 설치하고 모델 이름을 주면 몇 초 만에 첫 모델을 처리하기 시작합니다.

커뮤니티가 Hugging Face에 올린 Heretic 가공 모델은 수천 개에 달하고, MMLU·GSM8K 같은 표준 지표로 경쟁 abliteration 도구들과 비교한 독립 벤치마크도 있습니다.

동작 원리: 스코어러와 옵티마이저

Heretic의 구조는 두 부품입니다.

  • 모디파이어: 가중치를 실제로 바꾸는 알고리즘. 기본은 ARA(Arbitrary-Rank Ablation)이고, 고전적인 방향성 ablation(abliteration)도 지원합니다. 후자는 투영 ablation과 norm 보존(MPOA) 방식을 모두 지원합니다.
  • 스코어러: "이 모델이 얼마나 원하는 상태인가"를 점수로 매기는 플러그인. 기본으로는 거절률(keyword_rate)과 KL divergence(kl_divergence)를 씁니다.

이 둘을 Optuna의 TPE 최적화기가 연결합니다. 여러 스코어러를 동시에 켜서 점수를 공동 최적화하거나, 같은 스코어러를 다른 설정으로 여러 개 돌릴 수도 있습니다. 스코어러는 직접 플러그인으로 만들 수 있고, Scorer 추상 클래스를 상속해 get_score만 구현하면 됩니다.

목표 정의(스코어러) → TPE가 파라미터 탐색 → 모디파이어가 가중치 조정 → 스코어가 목표에 수렴

설치와 첫 실행

Python 3.10+ 환경에 하드웨어에 맞는 PyTorch 2.6+를 깔고 패키지를 설치하면 끝입니다.

pip install -U heretic-llm
heretic Qwen/Qwen3-4B-Instruct-2507

모델 이름만 바꾸면 됩니다. 기본 설정은 검열 제거(거절 억제)입니다. 다른 걸 하려면 저장소의 설정 파일(config.noslop.toml, config.nosyco.toml 등)을 고르거나 직접 씁니다. 설정은 작업 디렉터리의 config.toml 또는 HERETIC_CONFIG_FILE 환경변수로 지정합니다.

프로그램 시작 시 Heretic이 시스템을 벤치마크해 최적 배치 크기를 정합니다. RTX 3090에서 기본 설정으로 Qwen3-4B를 처리하는 데 30~40분 걸린다고 README는 밝힙니다.

VRAM이 부족할 때: 4비트 양자화

메모리가 부족하면 bitsandbytes의 4비트 양자화를 켤 수 있습니다. 모델을 양자화 버전과 비슷한 VRAM으로 처리할 수 있게 해 주는데, 정확도가 약간 떨어지는 대가가 있습니다.

# config.toml에서
quantization = "bnb_4bit"

"내 하드웨어에서 돌릴 수 있는 모델"의 범위를 넓혀 주는 옵션이지만, 양자화 자체가 정확도를 깎으니 중요한 용도라면 원본 정밀도로 결과를 비교해 보는 게 안전합니다.

재현성: Heretic Grimoire

Heretic의 독특한 기능 중 하나가 재현 가능한 모델입니다. Hugging Face에 업로드할 때 재현 정보 포함을 선택하면, 저장소에 reproduce 폴더와 reproduce.json 매니페스트가 들어갑니다. 환경이 완전히 같다면 바이트 단위로 동일한 모델을 다시 만들 수 있게 하는 장치입니다.

실행은 heretic --reproduce path/to/reproduce.json입니다. Heretic이 원래 환경과 현재 환경을 비교해 불일치를 짚어 줍니다. PyTorch는 하드웨어·드라이버·OS·패키지 버전이 전부 같아야 동일 결과를 보장하므로, 이 복잡성을 도구가 대신 관리해 주는 겁니다.

지원 범위: 어떤 모델이 되나

README는 "하드웨어에서 돌릴 수 있는 대부분의 dense 모델"을 지원한다고 밝힙니다. 멀티모달 모델 여러 개, 여러 MoE 아키텍처, 최신 하이브리드 모델도 포함입니다. 다만 "돌릴 수 있다"와 "Heretic이 잘 조정한다"는 다른 얘기이므로, 처음 쓰는 아키텍처라면 작은 모델로 먼저 결과를 확인하는 게 좋습니다.

처리가 끝나면 저장뿐 아니라 Hugging Face 업로드, 채팅으로 테스트, 표준 벤치마크 실행까지 그 자리에서 선택할 수 있습니다. 결과가 이상하면 설정을 바꿔 다시 돌리면 됩니다.

한계와 주의

먼저 라이선스입니다. AGPL-3.0은 도구 자체가 강합니다. 이걸 써서 만든 모델을 서비스로 제공하거나 수정해서 배포하면 소스 공개 의무가 생길 수 있습니다. 개인 로컬 사용과, 이 도구로 가공한 모델을 배포하는 것은 다른 문제이니 법무 검토가 필요합니다. 또한 원본 모델 자체의 라이선스도 별개로 확인해야 합니다.

둘째, 가중치 조정은 행동을 바꾸지만 능력을 보장하지 않습니다. 벤치마크에서 경쟁 도구와 비슷한 결과가 나왔다고 하지만, 특정 도메인에서 성능이 떨어질 수 있습니다. 셋째, 설정 파일이 1.x와 2.x 사이에 호환되지 않습니다. 예전 설정을 쓰려면 마이그레이션 가이드를 따라야 합니다.

도입 전 체크리스트

확인할 것 4가지

✓ 라이선스 — AGPL-3.0의 의무 범위, 가공 모델 배포·서비스 제공 시 소스 공개 검토

✓ 하드웨어 — 모델 크기와 VRAM, 필요하면 bnb_4bit 양자화

✓ 목표 — 어떤 성향을 바꿀지 스코어러·설정 파일로 먼저 정의

✓ 검증 — 처리 후 채팅·벤치마크로 결과를 직접 확인하는 절차

정리

Heretic은 "학습 없이 모델 성향을 바꾸는" 것을 일반인도 할 수 있게 만든 도구입니다. 스코어러가 목표를 정의하고, TPE 최적화기가 파라미터를 찾고, ARA·abliteration 모디파이어가 가중치를 조정합니다. RTX 3090급에서도 4B 모델을 30~40분에 처리합니다.

오늘 해 볼 일은 간단합니다. PyTorch 환경을 만들고 pip install -U heretic-llm로 설치한 뒤, 작은 모델 하나로 기본 설정을 돌려 보세요. 끝나면 저장·채팅·벤치마크 중에서 결과를 확인할 수 있습니다.
