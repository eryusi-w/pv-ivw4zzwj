GitHub 입문, Git과의 차이부터 기본 흐름까지

#GitHub#깃허브#Git#버전관리#개발도구#오픈소스#프로그래밍#개발입문#코딩#협업

"깃허브가 뭔가요?" 개발을 시작하면 가장 먼저 만나는 곳입니다. Git과 GitHub는 비슷해 보이지만 역할이 다릅니다. 초보가 알아야 할 개념을 정리했습니다.

Git과 GitHub의 차이

Git은 파일의 변경 이력을 저장하는 버전 관리 도구이고, GitHub는 그 저장소를 인터넷에 올려 공유하는 서비스입니다.

  • Git: 내 컴퓨터에서 파일 변경을 기록·관리
  • GitHub: Git 저장소를 온라인에 올려 팀과 공유

핵심 용어

처음엔 용어가 낯설지만, 실제로 쓰는 건 몇 개 없습니다.

용어뜻
저장소(Repo)프로젝트 파일이 모인 공간
커밋(Commit)변경 내용을 저장하는 행위
푸시(Push)내 컴퓨터 → GitHub로 업로드
풀(Pull)GitHub → 내 컴퓨터로 다운로드
PR(Pull Request)변경 사항을 검토·합치는 요청

기본 흐름

1. 저장소 만들기 (GitHub에서 New)
2. 내 컴퓨터에 클론 (git clone)
3. 파일 수정
4. git add → git commit (변경 저장)
5. git push (GitHub에 업로드)
6. 팀원이 pull로 받아서 확인

GitHub에서 할 수 있는 것

GitHub은 단순한 저장소 이상입니다.

  • 코드 공유·협업: 팀원이 동시에 작업하고 변경 내역을 추적
  • 이슈 관리: 버그·기능 요청을 정리
  • PR 리뷰: 코드 변경을 검토하고 합치는 과정
  • 프로젝트 포트폴리오: 공개 저장소로 실력을 보여줄 수 있습니다

비개발자도 쓸 수 있나요?

네. 문서 관리·버전 관리·팀 협업에도 쓸 수 있습니다. 다만 처음엔 복잡해 보일 수 있으니, 간단한 개인 프로젝트나 문서 버전 관리부터 시작하는 게 좋습니다.

정리

GitHub은 "코드를 공유하고 버전을 관리하는 곳"입니다. 처음엔 clone→수정→commit→push 흐름만 익히면 됩니다. 나머지는 필요할 때 배우면 됩니다.

참고: GitHub 공식 문서(github.com)와 Git 공식 문서(git-scm.com) 기준입니다.
