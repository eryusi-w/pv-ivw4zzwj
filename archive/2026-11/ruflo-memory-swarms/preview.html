Claude Code에 공유 메모리를 붙이는 ruflo

#ClaudeCode#ruflo#공유메모리#스웜#MCP#플러그인#MIT#에이전트오케스트레이션#벡터메모리#자동화

Claude Code로 작업하다 보면 이런 순간이 옵니다. "아까 하던 작업 이어서 해줘"라고 했는데, 에이전트는 앞 맥락을 전혀 기억하지 못합니다. 세션을 새로 열면 처음부터 설명해야 하고, 여러 에이전트를 동시에 돌리면 서로의 결과를 모릅니다.

ruflo는 이 문제의식에서 나온 "에이전트 메타 하네스"입니다. 예전 이름은 Claude Flow였고, Claude Code와 Codex 주변에 도구·메모리·스웜·보안을 얹는 실행 계층입니다. GitHub 별 8만 개를 넘겼습니다.

ruflo는 무엇인가: Claude Flow의 새 이름

README의 정의가 명확합니다. Agent = Model + Harness. 모델이 글을 쓰고, 하네스가 도구·메모리·루프·샌드박스·통제를 제공해 실제로 일하게 만듭니다. ruflo가 그 하네스입니다.

Claude Flow에서 이름을 바꾼 프로젝트로, 2025년 6월 첫 커밋부터 이어지는 계보를 문서로 공개하고 있습니다. 제공하는 것:

  • 100개 이상의 전문 에이전트와 조율되는 스웜
  • 자기 학습 메모리 — 성공 패턴을 기억해 다음 작업에 반영
  • 머신 간 연합 통신 — 다른 컴퓨터의 에이전트와 데이터 유출 없이 대화
  • 엔터프라이즈 가드레일 — 정책 강제와 보안 통제

MCP 도구 400개 이상, CLI 명령 60개 이상 규모라 표면이 넓지만, README는 "전부 배울 필요 없다"고 말합니다. init만 하면 나머지는 백그라운드에서 알아서 돌아갑니다.

메모리가 실제로 하는 일

핵심은 메모리 계층입니다. ruflo는 작업 결과를 벡터 메모리(RuVector)에 저장하고, 라우터가 다음 작업을 배정할 때 성공했던 패턴을 참조합니다.

주목할 부분은 로컬 벡터 검색과 대비 학습(contrastive update)이 LLM 없이도 동작한다는 점입니다. 임베딩과 학습 모듈은 필요하지만, "이 접근이 통했는가"를 기록하고 다음 라우팅에 반영하는 루프가 로컬에서 돌아갑니다.

에이전트 입장에서는 이런 식으로 작동합니다:

  • 작업 성공 → 패턴이 메모리에 축적
  • 비슷한 작업 → 유사 패턴을 검색해 우선 적용
  • 실패 → 대비 신호로 기록해 같은 실수 반복 방지

설치: 마켓플레이스와 플러그인

Claude Code 2.1.287 이상이 필요합니다. 세 개의 플러그인으로 나뉩니다.

/plugin marketplace add ruvnet/ruflo
/plugin install ruflo-core@ruflo
/plugin install ruflo-console@ruflo
/plugin install ruflo-mods@ruflo
/reload-plugins
/ruflo
플러그인역할
ruflo-core기반 도구
ruflo-console에이전트 콕핏(시각 콘솔)
ruflo-mods라우팅·정책 강제를 Claude Code 안에서 실행

Codex나 다른 MCP 지원 도구라면 프로젝트 초기화 마법사와 MCP 서버로 붙습니다.

npx ruflo@latest init wizard
npx -y ruflo@latest mcp start

Claude Code 없이 콘솔만 쓰고 싶으면 터미널 UI가 있습니다. npx ruflo tui로 Overview·Cost·Swarm·Events·Missions 화면을 볼 수 있습니다.

스웜과 미션 구조

메모리가 "개인 기억"이라면 스웜은 "팀 작업"입니다. 작업을 에이전트들에 나눠 주고, 각자의 결과를 모아 최종 산출물로 합칩니다. 콘솔의 Swarm 화면에서 실시간으로 누가 무엇을 하는지 볼 수 있습니다.

핵심은 사용자가 플러그인을 설치하고 평소처럼 Claude Code를 쓰면된다는 점입니다. 훅 시스템이 작업을 자동으로 라우팅하고, 성공 패턴을 학습하며, 백그라운드에서 에이전트를 조율합니다. "스웜을 명령하는 법"을 따로 배울 필요가 없습니다.

콘솔로 들여다보기

무엇이 돌고 있는지 보려면 콘솔을 엽니다. ruflo-console 플러그인이 에이전트 콕핏을 제공하고, Claude Code 없이도 npx ruflo tui로 같은 정보를 터미널에서 볼 수 있습니다.

화면은 Overview·Cost·Swarm·Events·Missions 다섯 축입니다. 지금 어떤 에이전트가 어떤 작업을 하는지, 얼마를 쓰고 있는지, 어떤 이벤트가 발생했는지를 한눈에 봅니다. 에이전트 수가 늘수록 이 관측 화면이 실질적인 가치가 됩니다.

보안과 권한 모델

메타 하네스는 강력한 만큼 권한도 큽니다. README는 mods가 "당신 계정의 권한으로 실행된다"고 명시합니다. 플러그인 코드를 리뷰한 뒤 설치하는 게 좋습니다.

엔터프라이즈 가드레일, 머신 간 연합 통신의 데이터 유출 방지, 감사 로그 같은 통제 장치가 문서화돼 있습니다. 팀 도입 시 권한 경계를 먼저 정하는 게 순서입니다.

비용과 관측성

에이전트가 늘어나면 토큰 비용도 늘어납니다. 콘솔에 Cost 화면이 따로 있고, TUI에도 비용 추적이 있습니다. 어떤 에이전트·모델 조합이 비싼지 보려면 이 화면부터 확인하세요.

LLM 호출 없이도 동작하는 로컬 벡터 검색 덕분에, 메모리 조회 자체는 비용이 들지 않습니다. 비용이 발생하는 건 실제 추론 호출뿐입니다.

한계와 주의

  • 복잡도 — 400개 MCP 도구와 수십 개 플러그인 생태계는 강력하지만 학습 곡선이 있습니다
  • 권한 — mods는 사용자 권한으로 실행되므로 출처를 확인해야 합니다
  • 메모리 오염 — 잘못된 패턴이 학습되면 반복될 수 있어, 초기에는 관찰하며 키우는 게 안전합니다
  • 의존성 — Claude Code 버전 요구사항(2.1.287+)이 있어 도구 버전을 맞춰야 합니다

어떤 사람에게 맞나

Claude Code를 매일 쓰면서 "세션 간 기억이 없다"는 게 불편했던 사람, 여러 작업을 병렬로 돌리고 싶은 사람, 에이전트 행동을 관측·통제하고 싶은 팀에 맞습니다.

반대로 가끔 Claude Code를 여는 수준이라면 플러그인 세 개와 메모리 계층은 과할 수 있습니다. 작게 시작해 core만 붙이고, 필요하면 console·mods를 추가하는 점진적 도입이 현실적입니다.

정리

ruflo는 "Claude Code에 두뇌를 붙인다"는 표현이 과하지 않을 정도로 야심 찬 프로젝트입니다. 단순한 플러그인 모음이 아니라 모델 주변의 실행 계층 전체를 재설계하려 합니다. 공유 메모리와 스웜이 실제로 체감되는 수준까지 왔다면, 에이전트 작업 방식 자체가 바뀔 수 있는 도구입니다.
