문제 제기: 무료 티어를 손으로 쌓을 때 생기는 일

요즘 AI 랩마다 무료 티어를 내놓습니다. 월 몇백만 토큰, 하루 몇천 요청. 하나만으로는 장난감이지만, 서른 개를 합치면 월 약 74억 토큰의 추론 용량이 됩니다. 문제는 이걸 손으로 관리한다는 겁니다.

서른네 개의 SDK, 서른네 개의 레이트 리밋, 서른네 군데의 실패 지점. 게다가 무료 티어 지형은 매주 바뀝니다. 새 모델이 나오고, 기존 모델이 사라지고, 한도가 바뀝니다. 손으로 추적할 수 있는 양이 아닙니다.

무료 티어를 하나의 OpenAI 호환 엔드포인트 뒤에 숨기고, 라우터가 알아서 고르게 하는 도구가 FreeLLMAPI입니다.

무엇인가: FreeLLMAPI

tashfeenahmed/freellmapi는 34개 무료 LLM 제공자, 635개 모델 엔드포인트를 하나의 /v1 API 뒤에 묶는 로컬 게이트웨이입니다. MIT 라이선스, GitHub 별 4.8만 개.

핵심은 세 가지입니다. 하나의 OpenAI 호환 엔드포인트로 모든 제공자를 통합하고, 키를 암호화해 저장하며, 라우터가 요청마다 최적 모델을 고르고 레이트 리밋에 걸리면 다음 제공자로 넘어갑니다. 키별 사용량도 추적해서 각 무료 한도를 넘지 않게 합니다.

로컬 우선(local-first)·단일 사용자 설계입니다. 제공자 키는 SQLite에 암호화돼 저장되고, 요청은 내 머신에서 활성화한 업스트림으로만 나갑니다.

설치: 스크립트 한 줄

Docker가 있으면 원라이너로 끝입니다.

curl -fsSL https://freellmapi.co/install.sh | bash

스크립트는 ~/freellmapi를 만들고 암호화 키를 생성하고 이미지를 받아 컨테이너를 띄웁니다. 다시 실행해도 안전합니다 — .env와 키는 유지되고 컨테이너만 최신으로 업데이트됩니다.

Windows는 데스크톱 .exe 설치 파일이 릴리스에 있습니다. macOS는 .dmg, Linux는 AppImage, Android는 Termux 가이드, Docker Compose도 지원합니다.

설치 후 http://localhost:3001을 열고, Keys 페이지에서 제공자 키를 추가하고, Fallback Chain 순서를 정하고, 헤더의 통합 API 키를 복사합니다. 그 키가 OpenAI SDK가 가리키는 자격 증명입니다.

폴백 체인: 무료 티어를 견디게 하는 핵심

무료 티어의 가장 큰 적은 레이트 리밋입니다. 한 모델이 일일 한도에 걸리면 요청이 그냥 실패합니다. FreeLLMAPI의 폴백 체인은 이걸 자동으로 처리합니다 — 한 제공자가 막히면 다음 제공자로 넘어가고, 키별 사용량을 추적해서 한도 안에서만 쓰게 합니다.

체인 순서는 대시보드에서 직접 정합니다. "이 작업엔 이 모델, 이 작업엔 저 모델"처럼 용도별로 나눌 수도 있고, 그냥 속도·품질 순으로 길게 늘어놓을 수도 있습니다. 다만 체인이 길수록 마지막엔 무료 티어가 아닌 유료 모델까지 내려갈 수 있으니, 어디까지 무료로 둘지는 직접 정해야 합니다.

# OpenAI 호환 클라이언트 설정 예시
OPENAI_BASE_URL=http://localhost:3001/v1
OPENAI_API_KEY=YOUR_KEY

지원 표면: 채팅부터 임베딩까지

단순 채팅이 아닙니다. OpenAI 스타일의 모든 표면을 지원합니다.

엔드포인트 용도
/v1/chat/completions, /v1/responses 일반 채팅, Codex CLI가 쓰는 responses API
/v1/completions 에디터 고스트 텍스트 자동완성
/v1/images/generations, /v1/videos/generations 이미지·영상 생성
/v1/audio/speech, /v1/audio/transcriptions 음성 합성·전사
/v1/embeddings, /v1/models 임베딩, 모델 목록
/v1/messages Anthropic Messages API — Claude 계열 클라이언트용

스트리밍·논스트리밍 모두 지원하고, 공식 SDK든 임의의 OpenAI 호환 클라이언트든 붙습니다. 라우터 자체가 MCP 서버 역할도 해서 에이전트가 세션 중에 모델 카탈로그를 들여다볼 수 있습니다.

코딩 에이전트 연결

Claude Code, Codex CLI, Gemini CLI, Cursor, Cline, Roo Code, OpenCode, Aider 등 주요 코딩 도구를 지원합니다. 설정 명령 한 줄이 라이브 카탈로그를 읽어 기존 설정을 백업하고 병합합니다.

npx freellmapi setup-claude --url http://localhost:3001 --api-key YOUR_KEY
# Codex는 launch-codex

npx freellmapi launch(Claude Code)와 launch-codex(Codex)는 자격 증명을 설정 파일에 남기지 않는 방식으로도 동작합니다. 키 관리도 터미널에서 됩니다 — 대시보드 세션 토큰으로 npx freellmapi keys add|list|remove|test를 씁니다.

카탈로그 자동 갱신과 프리미엄

무료 티어 지형이 매주 바뀌는 문제를 해결하는 장치가 있습니다. 라우터가 서명된 모델 카탈로그를 freellmapi.co에서 스스로 가져와서, 새 무료 모델·한도 변경·호환성 수정이 git pull 없이 반영됩니다.

다만 속도 차이가 있습니다. 무료 설치는 월간 스냅샷을 받아서 새 모델이 라이브 피드에 들어간 뒤 30일 뒤에야 받습니다. 프리미엄(연 19달러)은 당일 반영됩니다. 이 구분을 알고 선택해야 합니다.

한계와 주의

README가 스스로 밝히는 한계가 정직합니다. 프런티어 모델은 없고, 지연 시간이 들쭉날쭉하며, SLA가 없습니다. 그리고 하루 후반부가 되면 상위 모델이 일일 한도에 걸려서 실효 지능이 떨어지고, UTC 자정에 리셋됩니다.

또한 무료 티어는 언제든 사라질 수 있습니다. 제공자가 정책을 바꾸면 그 모델은 그냥 없어집니다. "무료로 영원히"가 아니라 "무료인 동안 최대한 뽑아 쓰는" 도구로 접근하는 게 맞습니다.

키 관리는 사용자의 몫입니다. 제공자 키를 얼마나 많이 등록하느냐가 쓸 수 있는 용량을 결정하고, 각 키의 분실·탈취 책임도 사용자에게 있습니다.

도입 전 체크리스트

확인할 것 4가지

✓ 제공자 — 실제로 쓸 수 있는 무료 티어가 몇 개인지, 키를 몇 개나 등록할지

✓ 폴백 체인 — 어디까지 무료로 둘지, 유료로 넘어가는 지점을 어디로 할지

✓ 용도 — 코딩 에이전트 백엔드로 쓸지, 일반 API 용도로 쓸지(품질 기대치가 다름)

✓ 갱신 — 무료 스냅샷 30일 지연을 감수할지, 프리미엄이 필요한지

정리

FreeLLMAPI는 "무료 티어를 손으로 관리하는" 문제를 게이트웨이 하나로 해결한 프로젝트입니다. 34개 제공자를 하나의 OpenAI 호환 엔드포인트 뒤에 숨기고, 폴백 체인과 키별 사용량 추적으로 한도를 자동 관리합니다.

오늘 해 볼 일은 간단합니다. Docker 원라이너로 띄우고 Keys 페이지에 무료 티어 키 두세 개만 등록해 보세요. 폴백 체인이 실제로 다음 제공자로 넘어가는 걸 보면 이 도구의 가치가 바로 체감됩니다.
