UI 품질을 스킬로 고정하는 interfaces

#interfaces#디자인스킬#UI리뷰#접근성#타이포그래피#색상#레이아웃#MIT#에이전트#프론트엔드

문제 제기: AI가 그린 UI, 왜 매번 어긋날까

AI에게 "대시보드 하나 만들어 줘"라고 하면 그럴듯한 화면이 나옵니다. 그런데 자세히 보면 여백이 제각각이고, 버튼 글자 크기가 미묘하게 다르고, 회색 텍스트의 대비가 기준 이하인 경우가 태반입니다.

모델이 디자인을 모르는 게 아닙니다. "좋은 UI"의 기준이 사람마다, 심지어 같은 사람 안에서도 프롬프트마다 다르기 때문입니다. 이 기준을 코드처럼 고정해 두면 이야기가 달라집니다.

UI 품질을 사람의 눈이 아니라 스킬 파일로 고정하는 저장소가 interfaces입니다.

무엇인가: interfaces 스킬 모음

Jakub Krehel이 만든 jakubkrehel/skills는 UI, 타이포그래피, 색상, 접근성, 레이아웃, 제품 문구를 다루는 에이전트 스킬 15개를 모은 저장소입니다. 저자는 디자인 엔지니어링 매거진 Interfaces(interfaces.dev)를 운영하며, 그 글들을 스킬로 옮긴 프로젝트입니다.

GitHub 별은 1.1만 개, 라이선스는 MIT입니다. 스킬 하나하나가 SKILL.md 문서이고, 에이전트가 작업 중 관련 스킬을 골라 기준표처럼 읽고 적용합니다.

핵심 아이디어 — "좋은 UI"를 매번 프롬프트로 설명하는 대신, 검증 가능한 규칙(대비비, 타이포 스케일, 포커스 링)을 스킬에 적어 두고 에이전트가 그걸 따르게 합니다.

스킬 구성: 15개가 덮는 영역

스킬은 크게 세 부류로 나뉩니다. 상시 참고용, 리뷰용, 그리고 화면을 직접 띄워서 시험하는 도구형입니다.

분류 스킬 하는 일
상시 기준 better-interface, better-ui, better-typography, better-colors, better-accessibility, better-layout, better-writing 화면·타이포·색·접근성·레이아웃·문구를 영역별로 점검하고 순위 매긴 리포트 반환
리뷰 interface-review 브랜치·PR·미커밋 변경에서 새로 생기거나 망가진 인터페이스 문제만 골라냄. 사용자가 직접 호출
분석·시험 explain-interface, break, state-machine, variant URL·스크린샷 해부, 모든 시나리오에서 컴포넌트 렌더링, 상태 전부 띄우기, 변형 비교
제작 build-design, teardown Figma·디자인 이미지대로 구현, 일러스트 레이어를 SVG/PNG/PDF로보내기

눈여겨볼 건 interface-review입니다. 전체 화면을 다시 채점하는 게 아니라 "이번 변경이 새로 만든 문제"만 봅니다. PR마다 돌리기 좋은 크기죠.

설치: npx 한 줄과 Claude Code 플러그인

스킬 프레임워크를 지원하는 에이전트라면 npx 한 줄이면 됩니다.

# skills 프레임워크 경유 설치
npx skills add jakubkrehel/skills

# Claude Code는 플러그인 마켓플레이스로도 가능
/plugin marketplace add jakubkrehel/skills
/plugin install interfaces@interfaces

설치 후에는 스킬이 자동으로 로드되고, 에이전트가 작업 맥락에 맞는 스킬을 골라 씁니다. 사용자가 직접 부르는 스킬(interface-review, break 등)과 에이전트가 알아서 참고하는 스킬(better-*)이 섞여 있다는 점이 특징입니다.

interface-review 사용법

가장 실용적인 진입점은 interface-review입니다. 작업이 끝난 뒤 한 번 호출하면 변경분에서 인터페이스 문제를 찾아 순위대로 보고합니다.

# Claude Code에서 직접 호출
/interface-review

# 또는 자연어로
"방금 PR에서 인터페이스 문제만 리뷰해 줘"

점검 축은 접근성(WCAG 2.2 기준), 레이아웃, 문구, 타이포그래피, 색상, UI 다듬기의 여섯 가지입니다. 접근성 축은 키보드·포커스 동작, ARIA, 접근 가능한 이름, 폼, 스크린리더 안내, 모션, 줌까지 봅니다.

better-* 스킬: 영역별로 파고드는 법

better-* 일곱 개는 각각 한 영역의 전문가 역할을 합니다. 예를 들어 타이포그래피가 걸리면 better-typography가 타입 스케일, 자간, 행간, 폰트 피처, 줄바꿈, 말줄임, 문장 부호까지 봅니다.

  • better-colors: 팔레트 생성, 시맨틱 토큰 이름 붙이기, 색상 형식 변환, 대비 측정
  • better-layout: 그룹핑, 정렬, 읽기 순서, 반응형 구조 — 번역·미러링에도 버티는 레이아웃
  • better-writing: 라벨, 에러 메시지, 빈 상태, 확인 문구를 제품 목소리에 맞게
  • better-accessibility: WCAG 2.2 기준으로 키보드·포커스·ARIA·폼·스크린리더를 점검

스킬끼리도 역할이 나뉘어 있습니다. 화면 전체를 한 번에 보는 better-interface와, 한 영역만 깊게 파는 개별 스킬이 공존합니다.

break와 state-machine: 상태를 직접 띄우는 스킬

이 모음에서 가장 독특한 건 "눈으로 확인"을 스킬로 만든 부분입니다. break는 고른 컴포넌트를 임시 페이지에 모든 시나리오로 렌더링해 스트레스 테스트합니다. 빈 데이터, 아주 긴 텍스트, 에러 상태 같은 도달 가능한 모든 경우를 한 화면에 띄우는 거죠.

state-machine은 컴포넌트의 모든 상태를 목업 데이터와 전환 스위처와 함께 렌더링합니다. 상태별로 따로 작업하고 싶을 때 유용합니다. variant는 같은 컴포넌트의 여러 변형을 만들어 비교하며 고르게 해 줍니다.

explain-interface와 teardown: 남의 화면 해부

explain-interface는 라이브 URL이나 스크린샷을 주면 그 화면이 어떻게 만들어졌는지 — 어떤 기법과 구조로 구현됐는지 — 를 설명합니다. 잘 만든 사이트의 UI를 벤치마킹할 때 쓸 수 있습니다.

teardown은 반대 방향입니다. 개체를 고르면 기술 일러스트를 만들고, 색을 바꾸고, SVG·PNG·PDF로보낼 수 있게 합니다. 문서용 다이어그램 제작에 가깝습니다.

한계와 주의

스킬은 기준을 줄 뿐, 판단을 대신하지 않습니다. WCAG 2.2를 "통과"해도 실제 사용성이 좋은지는 별개이고, 브랜드 가이드와 충돌하는 제안이 나올 수도 있습니다.

저자도 스스로 밝히듯 이 스킬들은 interfaces.dev 매거진의 글을 옮긴 것입니다. 특정 회사의 디자인 시스템 표준이 아니라 "일반적으로 좋은 UI"의 기준이므로, 팀 규칙이 있으면 그쪽이 우선입니다. 또한 15개 스킬을 한꺼번에 넣으면 에이전트가 컨텍스트를 많이 쓰므로, 필요한 영역만 골라 쓰는 게 낫습니다.

도입 전 체크리스트

확인할 것 4가지

✓ 설치 경로 — skills 프레임워크(npx)와 Claude Code 플러그인 중 환경에 맞는 쪽

✓ 호출 시점 — interface-review를 PR마다 돌릴지, 큰 작업 뒤에만 돌릴지

✓ 팀 기준 — 접근성·타이포 규칙이 기존 가이드와 충돌하지 않는지

✓ 범위 — 15개 전부보다 필요한 스킬만 활성화해 컨텍스트 절약

정리

interfaces는 "좋은 UI"를 매번 말로 설명하는 대신 스킬 파일로 고정한 모음입니다. 접근성부터 제품 문구까지 여섯 축을 커버하고, PR 변경분만 골라내는 interface-review가 가장 실용적인 진입점입니다.

오늘 해 볼 일은 간단합니다. npx skills add jakubkrehel/skills로 설치하고, 진행 중인 브랜치에 interface-review를 한 번 돌려 보세요. 지금까지 몰랐던 어긋남이 리포트로 나옵니다.
